## 2. Protocol module (pure functions)

- [x] 2.1 Add `main/service/googleFreeProtocol.ts` with `buildChromeQuery`: a hand-built query string with a repeated `q` (never `q[]`), percent-encoded text and per-line truncation to 5,000 characters.
- [x] 2.2 Add chunk planning: at most 50 `q` and 6,000 encoded bytes per request (counting `client`, `sl` and `tl`), an oversize single line alone in its chunk, blank lines left out of the request and restored by position.
- [x] 2.3 Add response parsing for both shapes (string items and `[text, language]` items) that validates the count, the item shape and empty items, and returns a typed protocol failure instead of partial results. (Amended 2026-10-15: the first version rejected only an all-empty answer; the live smoke then saw one batch of 20 answered with 8 empty items, so any empty item now rejects the whole response. Evidence in design D3; the matching spec scenario was added.)
- [x] 2.4 Add abuse-page classification: 429 or 403 plus `unusual traffic`, `automated queries` or `/sorry/` (case-insensitive; string or already-parsed object bodies); everything else is an ordinary failure.
- [x] 2.5 Amendment 2026-10-15 (design D3, OQ7): let `parseChromeResponse` mark a rejection that is only about empty items (`emptyItems`, the number of empty items; 0 for count, shape and non-array rejections), so the lane can tell a transient degraded answer from a structural one. (Done 2026-10-15: `ChromeParseResult` carries `emptyItems` on every rejection; 2 protocol tests, red first; 4 hand-made mutations of the marker were caught.)
