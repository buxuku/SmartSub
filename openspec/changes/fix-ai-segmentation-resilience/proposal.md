## Why

[#507](https://github.com/buxuku/SmartSub/issues/507)：选择「AI 语义断句」后，几乎每个窗口都落到「部分或全部 AI 断句未通过，已使用规则断句」。日志（faster-whisper + SiliconFlow，12 个窗口、并发 3）里 8 个窗口降级，任务耗时 30.5 分钟，171 条字幕只剩 125 条。

逐窗口读日志，有三个相互独立的原因叠加，才把成功率压到这个程度：

1. **校验比设计更严。** 校验只去掉空白后做字符串等值，任何标点、大小写、个别字母的出入都会让整窗判错。原设计 D3 写的是「容忍少量标点级差异并定位 diff」，D4 写的是「校验在容差内放行轻微差异时用 diff 对齐兜底」，实现里却没有这一档容差。反馈重试也救不回来：模型会把同样的偏差再来一遍。
2. **保留的是最后一轮，不是最好的一轮。** 重试的输出可能比首轮更差（改坏文本、请求失败），而窗口最终取最后一轮，已有的可用答案被一并丢掉。
3. **请求没有时限。** OpenAI SDK 默认单次等 10 分钟，并把超时再重发两次，一个卡住的请求会占住窗口 30 分钟。

| 窗口  | 日志里各轮相似度 / 超长段数           | 实际发生了什么                                                           | 对应修复                   |
| ----- | ------------------------------------- | ------------------------------------------------------------------------ | -------------------------- |
| 5     | 99.2% → 99.2% → 95.5%                 | 极小偏差，三轮重复同样的偏差                                             | 容差                       |
| 11    | 99.2%(超长 1) → 40.8% → 40.8%         | 首轮几乎正确；重试改坏，第三轮与第二轮结果相同（疑似原样重复）却仍被重发 | 容差 + 保留最佳 + 重复即停 |
| 6、12 | 100.0%(超长 1) → 99.0% / 97.2% → 同上 | 首轮内容完全正确，仅一段超长；重试把它改坏，最终以最后一轮为准           | 保留最佳（+ 容差）         |
| 9     | 100.0%(超长 1) → 39.2% → 请求超时     | 首轮可用，重试输出被改坏，第三轮请求卡住 30 分钟                         | 保留最佳 + 请求限时        |
| 7     | 100.0%(超长 1) → 请求超时             | 首轮可用，重试请求卡住 30 分钟，整窗连同可用答案一起降级                 | 保留最佳 + 请求限时        |
| 2、8  | 28.6%–50.8%（8 的首轮 93.2%）         | 模型确实在大幅改写                                                       | **不在本次范围**，仍会降级 |

按日志里的相似度与超长数反推，8 个降级窗口里约 6 个能被救回；窗口 2、8 是模型真的在改写，需要换更强的模型。

## What Changes

- **容差校验**：只比较字母与数字（NFKD 折叠、忽略大小写、标点与空白），相似度不低于 0.96 即放行。放行后按模型选的断点在原文中的位置重新切分，**字幕文字始终来自转写本身**，不会带入模型的改动。超出容差仍判为改写，照旧定位并反馈重试
- **保留最好的一轮**：各轮中内容可用优于被改写，同为可用时超长段更少者优先，严格逐字一致优于容差放行；反馈提示基于最好的一次而不是最新一次；模型原样重复同一答案则不再重发；重试轮请求失败时沿用已有可用答案，且不计为「服务不可达」
- **请求限时**：窗口尚无可用答案时，每次请求尝试最多等 300 秒（与 Ollama 一致）；已有可用答案后的重试，限时取「此前最慢请求的 2 倍」（下限 60 秒、上限 300 秒）并且不做传输层重发。`TranslationRequestOptions` 新增 `timeoutMs` / `maxRetries`，由 OpenAI 兼容与 Azure OpenAI 服务透传给 SDK
- **日志可自查**：每个窗口记录校验失败的轮次、内容是否可用、相似度与超长段数；降级原因区分「内容被改写 / 请求失败 / 无法对齐」；容差放行、重复答案停止、重试失败沿用答案都有记录
- 文档补充容差、限时与日志自查（`docs/docs/advanced/ai-refine.md`）
- 不在本次范围：
  - 模型大段改写原文（窗口 2、8）仍会降级
  - AI 字幕校正与常规翻译仍沿用 SDK 默认的 10 分钟限时
  - 温度（实现为 0.3，原设计为 0.1）与提示词示例不变
  - 服务整体不可用时没有熔断，每个窗口各自等到限时后才降级
