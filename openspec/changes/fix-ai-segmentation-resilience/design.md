## Context

AI 断句每个窗口的流程是：LLM 在原文里插 `<br>` → `parseBrSegments` → `validateSegmentation`（内容 + 限长）→ 不通过则带反馈重试（最多 2 轮，共 3 次）→ 对齐到词/cue → 物理护栏；任何一步失败，该窗口降级为规则 cue。

#507 的日志显示，降级的窗口里绝大多数并不是模型「不会断句」，而是流程把本来可用的答案丢了（见 proposal 的逐窗口表）。三个原因分别落在校验、重试选择、请求时限三处，彼此独立，所以拆成三步修，每步都有各自的失败测试。

约束：

- 不改协议与提示词：模型端行为不变，只改我们如何判定和使用它的答案
- 字幕文字必须来自转写本身，容忍模型的出入不能把模型的改动带进字幕
- 不新增依赖；`diff`（jsdiff）已是生产依赖，校对页也在用
- 校验函数保持纯函数、可单测

## Goals / Non-Goals

**Goals**

- 标点、大小写、个别字母级的偏差不再让窗口失败，也不再触发无谓的重试
- 重试永远不会让结果比已有答案更差
- 单个卡住的请求不会长时间占住一个窗口
- 降级原因能从日志里直接读出来

**Non-Goals**

- 救回模型大段改写的窗口（相似度 30%–50%），那需要换模型或改提示词
- 改动 AI 字幕校正、常规翻译的限时与重试
- 引入熔断：服务整体不可用时仍由各窗口各自等到限时后降级

## Decisions

### D1: 用「骨架」比较内容，相似度阈值 0.96

骨架 = 文本经 NFKD 折叠、转小写后，只保留字母、数字与组合符号的序列（忽略标点、空白、符号；全角/半角、预组合/分解形式视为同一字符）。相似度 = `1 − 编辑量 / (原文骨架长 + 模型骨架长)`，替换计 2 次编辑，与 `difflib` 的 ratio 同口径。不低于 0.96 放行，即编辑量上限为 `floor(0.04 × (n + m))`；该上限小于 1 时（极短文本）不放行任何字母级改动，保持既有的「插字 / 删字判不通过」单测语义。

0.96 沿用原设计 D3 所参照的同类实现的门槛（`2026-07-28-add-ai-subtitle-refine`），不是本项目的实测值；它是单个常量 `MIN_ANCHOR_SIMILARITY`，若之后发现过松或过紧可单独调整。

用 jsdiff 的 `diffArrays` 并传 `maxEditLength`：编辑量超过上限就立即放弃，不会在垃圾输出上耗时；先剥掉公共前后缀，让常见的「大部分一致」输入几乎零成本。

替代方案：

- **只放行标点级差异**：日志里 99.2% 的偏差不一定是标点，太窄
- **放行后直接采用模型副本**：会把模型的改字带进字幕，而且对齐是按字符数做的，副本与转写长度不同就会错位（运行器测试里有一条专门卡这个）
- **`difflib` 式整段相似度但不定位**：只能判断「像不像」，无法把断点映射回原文

### D2: 放行后按断点重锚定到原文，字幕文字始终取自转写

diff 给出模型骨架与原文骨架的对应关系，模型的每个断点映射为原文骨架的一个位置，再换算成原文字符串的切点：

- 紧跟在前一个内容字符之后；收尾标点（句号、逗号、右引号、右括号等）归左
- 起始引号、左括号、货币符号归右
- 被删除的字符归左，不会凭空产生空段；纯标点段并入前一段
- 不从码点中间切开（代理对、NFKD 展开的码点）

校验器因此多返回 `alignSegments`：严格等值时是模型分段，容差放行时是按断点切开的原文。限长检查与后续对齐都基于它，所以容差内的偏差同样受长度限制约束。

### D3: 保留最好的一轮，而不是最后一轮

`compareValidations` 的优先级：内容可用优于被改写；同为可用，超长段更少者优先，再比超出总量，最后严格逐字一致优于容差放行；同为被改写，相似度高者优先。反馈提示基于最好的一次，不是最新一次，因为最新一次可能是退步的垃圾输出。

模型对反馈原样重复同一答案时，再发请求只会得到同一个答案，直接停。重试轮的请求失败（超时、网络抖动）且手里已有可用答案时，沿用它并记一条 warning，不计入「服务不可达」，也就不会推动整个阶段降级。首轮失败、取消、配置错误仍按原规则上抛。

### D4: 请求限时，区分「还没有可用答案」与「只是想再改善一下」

| 阶段                           | 单次尝试限时                             | SDK 传输层重发                               |
| ------------------------------ | ---------------------------------------- | -------------------------------------------- |
| 首轮，以及尚无可用答案时的重试 | 300 秒                                   | 保留 SDK 默认（2 次），照顾 429 / 5xx 的退避 |
| 已有可用答案后的重试           | `min(300, max(60, 2 × 此前最慢请求))` 秒 | 0 次，失败就沿用已有答案                     |

300 秒与现有 Ollama 的上限一致，给慢速本地模型和推理型模型留余量。

需要说明的限度：SDK 会把超时也当作可重发的错误，所以**完全卡死的窗口最坏仍约 3 × 300 秒 = 15 分钟**，不是 5 分钟；#507 里是 3 × 600 秒 = 30 分钟。这是有意的取舍：把首轮的重发次数降到 1 能把最坏值再压到 10 分钟，但会削弱 429 限流下的自愈，对 SiliconFlow 这类按 RPM 限流的服务不划算，所以先不动。

时限经 `TranslationRequestOptions.timeoutMs` / `maxRetries` 逐请求传给 SDK，而不是改 client 的默认值：同一个 client 还服务翻译与校正，不应被断句的时限影响。没有用 `AbortSignal.timeout`：`translateWithOpenAI` 会把任何已中止的信号转成 `TaskCancelledError`，超时会被误判为用户取消。

### D5: 日志要能回答「为什么降级」

- 每轮校验失败：`validation failed (round r/n, contentOk=…, similarity …%, lengthViolations …)`
- 降级原因三选一：`content differs from the original`、`request failed`、`could not be aligned to the window`
- 容差放行：`copy drifted from the transcript (similarity …%, within tolerance)`
- 重复答案停止、重试请求失败沿用答案各一条

### D6: 与现有规范的偏差，必须显式记录

1. 规范与设计写的是「规范化等值校验」「容忍少量标点级差异」，实现却是去空白后严格等值。本变更补上容差，并把容差从「标点级」扩大为「字母数字级、不超过 4%」，是设计意图的超集，因为日志里的偏差不都是标点。delta spec 据此改写条款
2. 原规范「重试 2 轮后校验仍不通过则降级」与代码不符：代码历来接受「内容可用但有超长段」的答案，交物理护栏二次切分（设计 D8「宽进严出」）。delta spec 顺带把措辞改为「所有答案的内容都不可用才降级」

## Risks / Trade-offs

- **容差放行了模型的细小改字，断点可能偏离一个词** → 字幕文字不受影响（取自原文）；断点按 diff 局部映射，偏差只出现在被改动的词附近；限长与物理护栏照常兜底
- **0.96 不是本项目实测值** → 单一常量，可按真实使用反馈调整；被拒绝的一侧仍有反馈重试与降级兜底
- **完全卡死的首轮窗口最坏仍约 15 分钟** → 见 D4；其他窗口并发不受影响。如需更紧，可只对首轮把重发降到 1
- **容差校验后再做限长检查，可能比旧逻辑多一次「因超长而重试」** → 重试只在已有可用答案上改善，限时更紧、失败沿用已有答案，代价有上限
- **未用真实模型验证** → 行为由脚本化的假模型与随机性质测试覆盖（见 tasks）；真实服务商上的效果需要实际跑任务确认

## Migration Plan

无数据迁移，行为即时生效，已保存的任务配置与 Recipe 不受影响。回滚即还原提交；`TranslationRequestOptions` 新增的两个字段是可选的，其他调用方不受影响。
