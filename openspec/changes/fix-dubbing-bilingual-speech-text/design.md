## Context

配音有两条入口，对双语字幕的处理不一致：

- **流水线配音阶段**：`pickDubTextSource` 优先取纯译文，只有双语交付物时用校对 sidecar 的译文列重建纯译文，写成临时目录里的 `pipeline-dub/<uuid>-<hash>.srt` 再建会话。顺延字幕的展示文本另按交付字幕还原（`resolveDubSubtitle`），所以成片字幕仍是双语。
- **工作台**：`dubbing:loadSubtitle` → `createDubbingSession` 把字幕行的 `\n+` 压成空格，整行当配音文本。载入「原文 + 译文」双语字幕时，原文与译文被连着朗读。

校对 sidecar（`ProofreadDataFileV2`）记录了任务写出的全部字幕：`meta.sourceFile`、纯译文中间产物 `targetFile`、主交付物 `finalTargetFile`，以及 `sourceSubtitleFiles / translatedSubtitleFiles / tempSrtFile / tempFinalSubtitleFile`（经 `subtitleOutputFilesToSave` 标注每个路径的内容类型），还有 `translateContent`（`onlyTranslate / sourceAndTranslate / translateAndSource`）和每行的 `source / target`。

交付字幕的版面由 `layoutSubtitleColumns` 决定：每一列折成一行（任一侧是 CJK 时不加空格，否则用空格连接），两列再用换行连接；旧模板保留多行列。

工作台的会话已有两处相关设施：说话人元数据按「同起止时间优先，行数一致按序号」把解析出的字幕行与 sidecar 行配对；顺延字幕导出已支持 `displayTextByIndex`（流水线在用）。

## Goals / Non-Goals

**Goals:**

- 载入任务交付的双语字幕时，工作台只念译文，与流水线「纯译文优先」的契约一致。
- 导出的顺延字幕（会被烧进成片）仍是双语，不因为只念译文而悄悄变成单语。
- 无法确定时退回既有行为，而不是猜；不是双语交付物的字幕逐项不变。

**Non-Goals:**

- 没有 sidecar 的外部双语字幕：没有任何记录说明哪一行是译文，见决策 1。
- 界面上的提示或「只念某一语言」开关。
- 迁移已保存的旧会话。
- 修改流水线配音阶段（它的临时纯译文字幕不是 sidecar 的交付路径，不会触发新逻辑）。

## Decisions

**1. 只用 sidecar 回答「这是不是双语交付物、顺序如何」，译文块的位置在所载文件上定位，念的文字取文件本身。**
`bilingualContentType(meta, path)`：`translateContent` 必须是双语；路径是 `sourceFile`、`targetFile`（纯译文）或任何「源语言」输出时一律排除，即使共用路径；只有 `finalTargetFile` 或内容类型等于 `translateContent` 的输出才算交付物。
备选：(a) 像流水线一样直接念 sidecar 的 `target`——否决：工作台允许直接改字幕文件，sidecar 文本会与所载文件脱节，用户载入的才是他要念的文字；而且行数对不上 sidecar 时就没有文字可念。(b) 不用 sidecar，按语言检测给每行分类——否决：分不出源与译，中→日、英→法这类同文字或相近语言对会误判。(c) 按行数猜（偶数行取后半）——否决：旧模板的多行列与单语多行字幕会被误伤。

**2. 译文块是该行去掉空行后的「末尾」（原文在前）或「开头」（译文在前）的若干行，先用 sidecar 的译文匹配，失败再用原文匹配另一端；比较时忽略全部空白。**
定位只在块与 sidecar 文本完全相等时成立，所以不会把别的内容当译文。忽略空白是因为交付排版把一列折成一行时 CJK 之间不加空格、其它语言用空格，与 sidecar 里的原文本空白形式不一致。译文自己占多行（旧模板）时，朗读文本是该块各行以空格连接的一行，与此前整行压平的做法一致。定位不到的行保持原行为，记入 `unresolved` 并写警告日志。
用原文做回退是为了「用户手改了交付字幕里的译文，sidecar 里还是旧译文」：原文行仍能认出，余下的就是新译文。
备选：把行对半分——否决，译文行数不一定等于原文行数。

**3. 行配对复用说话人元数据的规则，抽成共用函数 `alignSidecarCues`。**
同起止时间优先（每个 sidecar 行只用一次），否则在两边行数相同时按序号，其余视为没有安全配对。这是行为不变的抽取，说话人元数据与新逻辑从此用同一条规则，不会出现一边认得、一边不认得。对不上的行当作未解析，不猜。

**4. 展示版面 `display = { lines, from, to }` 随会话行落盘，导出时用 `composeDisplayText` 还原。**
`lines` 是交付字幕该行去空行后的各行，`[from, to)` 是译文块。未编辑（会话文本等于译文块的朗读文本）时原样还原，包括多行译文的原始换行；编辑过则用编辑后的文本（压成一行）替换译文块，清空则只剩原文行。导出通过已有的 `displayTextByIndex` 传入，仅在导出顺延字幕时构建；时间轴仍取对齐规划结果。
为什么落盘而不是导出时重新推导：导出时 sidecar 可能已被重新校对改过、也可能不在了；会话文本本来就是创建时的快照，版面应与它同时确定。`display` 是可选字段，`session.json` 版本号仍为 1：旧会话没有它，按原语义加载与导出。工作台的文本编辑只改会话文本，不回写字幕文件，也不增删行，所以按行号索引的 `display` 始终有效。IPC 的 `cueView` 是逐字段构造的，`display` 不会暴露给渲染层。
备选：导出时重新读取交付字幕并重新定位——否决：要再次依赖磁盘上的文件与 sidecar，而字幕文件一变会话本来就要重建。

**5. 语言：只有真正定位到译文行时才采用 sidecar 的目标语言；检测语言按实际要念的文本算。**
`dubbingSubtitleLanguage` 原本就不为双语交付物给出语言（整份双语不属于任一语言）。现在当至少有一行定位成功时，会话字幕语言取 sidecar 的目标语言，调用方显式传入的语言仍然优先；全部行都没定位到时不采用，免得把一份仍是整行念的双语标成译文语言。

**6. sidecar 归属范围扩大到任务写出的全部字幕。**
原来只认 `sourceFile / targetFile / finalTargetFile`。第二交付格式（如同时输出 `.vtt`）与合成阶段保留的带时间轴副本 `tempFinalSubtitleFile` 载入工作台时认不出 sidecar，也就无法判定为双语交付物。改为同时并入 `subtitleOutputFilesToSave(meta, translateContent)` 的全部路径。副作用是这些文件现在也能拿到 sidecar 的说话人信息，与同一份交付物的 `.srt` 一致。

**7. 流水线不动。**
`materializeDubSubtitle` 总是把纯译文写到临时目录，那不是 sidecar 的任何交付路径，`bilingualContentType` 对它返回 undefined，新逻辑不触发；`createDubbingSession` 对它的行为与此前逐项相同。

## Risks / Trade-offs

- [译文定位错了，念出原文或半句] → 定位只在块与 sidecar 文本忽略空白后完全相等时成立，否则整行念（既有行为）并写警告日志；测试覆盖两种顺序、折行与 CJK 无空格、多行译文、手改译文、行数对不上的 sidecar、不同格式。
- [原文与译文相同的行（专有名词、音符）] → 译文块取末尾或开头一行，念出的文字相同，结果正确。
- [说话人名前缀] → 交付字幕的说话人名写在整段文本之前（`[名字] 文本`）。原文在前时它落在原文行，不会被念；译文在前时它属于译文行，朗读文本保留它，与修复前一致（`[Speaker N]` 形式的默认前缀仍由配音文本规范化去掉）。两种情形都用生产排版函数写出的字幕验证过能定位译文，展示版面保留前缀。
- [用户把交付字幕里的原文和译文都改了] → 两列都对不上，整行念并写警告日志；此时与修复前一致。
- [没有 sidecar 的外部双语字幕仍整行念] → 已知限制，不做；没有任何记录说明语言顺序，强行按语言检测会误伤。
- [旧会话保持当时保存的文本] → 不迁移；`display` 缺失时按旧语义，不会出错。
- [`display` 让 `session.json` 变大] → 每个双语行多存一份交付文本，量级与字幕本身相同。
- [编辑后多行译文在顺延字幕里合并成一行] → 编辑后的文本本来就是一行；未编辑的行逐行还原。
- [归属范围扩大影响说话人元数据] → 只对同一任务、同一 sidecar 登记过的路径生效，与同一份交付物的 `.srt` 行为一致。
