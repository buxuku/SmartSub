## Context

一个任务的配置现在分散在四处：

- **工具栏**（`InlineConfigBar`，不换行的一行，最小窗口宽度 1024，侧栏 64px）：语音模型 → 视频语言 → 翻译成 → 翻译服务 → 词库 → 生成摘要 → 场景 → 断句与精修 → 字幕格式（该控件实际含格式与「输出内容」：仅译文 / 双语）。
- **场景弹层**（`ScenarioPresetControl`）：6 行（5 个场景 + 「专家自定义」），选中即 `applyScenarioPreset` 批量写入 `ALL_PRESET_FIELD_KEYS` 里的字段；最后一行 `onOpenAdvanced`。
- **「高级选项」侧栏**（`AdvancedSheet.tsx`，约 1290 行，任务页与向导共用）：场景横幅 → 转写（内封字幕、字幕效果 4 张卡 + 自定义旋钮、断句精调、提示词、保存音频、faster-whisper 折叠区、角色分离、语气词策略、参考文稿、翻译风格）→ 输出与保存（排版、源 / 译文命名、去标点、字幕输出格式）→ 执行（并发、翻译重试）。
- **断句与精修弹层**（`AiRefineControl`）：断句方式与 AI 校正，已经是它们的唯一入口。

场景与字幕效果写的是同一批字段：每个场景预设里都有 `subtitleOutcome`，还带 VAD、`fasterWhisper*` 等。`scenarioPreset` 只是一个界面用的标签字段，随任务配置一起存进草稿 / 快照 / 配方，`main/` 与 `types/` 里没有任何引用。`detectCurrentPreset(formData)` 用「预设里写了的字段必须相等，没写的字段必须是 undefined / null / 空串 / false」来判断当前配置还是不是那个场景，否则返回 `custom`。

`getUserConfig` 返回 `{ ...defaultUserConfig, ...已存配置 }`，其中 `defaultUserConfig` 带 `maxSubtitleChars: 0`、`speakerDiarizationCount: 0`（`0` 的含义是智能 / 自动）。于是全新用户的表单里这两个键就是 `0`，在上面的规则下被当成偏离。已在真实函数上验证：默认值喂进 `detectCurrentPreset` 得到 `custom`，去掉这两个 `0` 得到 `balanced`，各只留一个 `0` 也是 `custom`。e2e 里 `^(通用均衡|专家自定义)$` 的容错正则是这个状态的旁证。

引擎侧：`resolveEffectiveSettings` 只被 builtin / faster-whisper / funasr / qwen / fireRed / parakeet 引擎调用，`cloudAsrEngine` 与 `localCliEngine` 不用它，所以字幕效果档位对云端听写与本地命令行引擎没有任何作用；VAD 滑块已经通过 `supportsTaskVadField` 对这两个引擎隐藏。`subtitleFillerPolicy` 只被 AI 校正（`correctionRunner`）读取。

已有的规格 `transcription-outcome-presets` 要求「向普通用户提供」字幕效果档位；场景预设是后来加的，没有对应的规格（`openspec/specs/` 里没有它，文档站也没有讲它）。

## Goals / Non-Goals

**Goals:**

- 普通用户用「场景」一步到位，看不到、也不需要理解 VAD、解码、上下文这类机制；改过细项后只看到「已调整」，不被吓到。
- 高频项靠前、专家项集中到一个有名字的入口；一个设置项只在一处出现。
- 面板、提示、文案、文档里同一个东西只有一个名字，提示指向的路径与实际一致。
- 全新用户一打开，场景按钮就是「通用均衡」。

**Non-Goals:**

- 任务配置字段、预设取值、`convertToCustomOutcome`、引擎映射与流水线的任何改动；无数据迁移。
- 合并「词库 + 生成摘要」、并发数挪到列表底部、语气词策略挪进「断句与精修」弹层（第二期）。
- 新增工具栏控件，或让 1024px 下的工具栏更宽。
- 版本号与 `Changelog/`（发版时写）。

## Decisions

**1. 三层渐进披露：工具栏 → 更多设置·常用 → 更多设置·专家；一个设置项只在一处。**
工具栏放「每个任务都要定的」，常用页放「偶尔会改、普通用户也看得懂的」，专家页放「改它需要懂机制的」。重复的控件（侧栏里的「字幕输出格式」、场景横幅）直接删除，而不是做成两处同步。
备选：只在现有侧栏里加分组标题——否决：长度与混排没变，专家项依然没有自己的入口；备选：把专家项全部挪进「设置」页——否决：这些参数是任务级的，要随任务快照 / 配方走。

**2. 场景是起点，不是模式：显示「已调整」，不显示「专家自定义」。**
场景弹层是最短的路径，所以让它承担全部意图选择。改过细项后，用户并没有"进入了专家模式"——他只是在某个场景的基础上动了几项，所以按钮继续显示场景名，在旁边加一个小圆点（屏幕阅读器读作"已调整"），点开弹层在脚注里列出动了哪几项并给出「恢复为『X』」。只有显式 `scenarioPreset === 'custom'`（选了「手动调节」，`convertToCustomOutcome` 把场景置为 `custom`）才显示「自定义」。
弹层里去掉「专家自定义」一行：它不是一个场景，而是一个状态；进入细调的入口换成脚注里的「更多设置」「专家设置」。
备选：保留「专家自定义」，只是改名——否决：仍然让普通用户以为改一项就"离开了场景"，并且在全新用户那里它是第一眼看到的东西；备选：改过任何项就自动换成新的"自定义 N"——否决：增加状态、没有收益。

**3. 偏离判定：中性值规则 + `getPresetDeviations`。**
`detectCurrentPreset` 的遍历抽成 `getPresetDeviations(formData, presetId = 基础场景)`，返回偏离的键；`detectCurrentPreset` 变成"有偏离就 `custom`，否则是基础场景"，行为对所有已测输入不变，只修正下面两点：

- 没写进预设的字段，中性值是 `undefined / null / 空串 / false`，另加 `0`——但只对 `maxSubtitleChars`、`speakerDiarizationCount`（`0` 在这两个字段里就是"智能 / 自动"，默认配置本来就带着它）。其它字段的 `0` 仍是偏离，例如 `subtitleMaxGap: 0`（不按停顿断句）是用户有意的调整。
- `subtitleOutcome` 缺省（老快照）时按 `inferDisplayOutcome` 推断出的档位比较，不算偏离。

键到「人话分组」的映射放在同一个文件（断句长度、断句精调、AI 校正、语气词处理、角色分离、识别策略、VAD 与抗重复、解码参数、翻译风格、字幕排版），脚注与专家 tab 圆点都用它；专家 tab 的圆点只看属于专家页的分组。
备选：在 `getUserConfig` 里把默认的 `0` 去掉——否决：`0` 是 `AiRefineControl` 等控件读取的真实默认值，改默认配置会牵动存储与自动化；判定的问题就该在判定里解决。

**4. 「字幕效果」降级为专家页的「识别策略」（已确认）。**
它回答的是「识别得准不准」（抑制重复与幻觉 vs 保留短词与轻声），本质是一个专家取舍；普通用户的意图已经由场景表达（每个场景都带着合适的档位）。「文字最准 / 均衡 / 最干净最稳」的名称与说明、`recommended` 徽标、样例对比、faster-whisper 的专属说明都原样保留，只是搬家、改成紧凑单选 + 当前档位的一句话说明；第四项由「自定义」改称「手动调节」，才展开上下文 / VAD / 抗重复（逻辑与 `convertToCustomOutcome` 不变）。规格原文写的是「以视频类型为主标签、效果名为副标签」，而界面早就是「效果名作标题、『适合…』作说明」，借这次改规格把它写成与实际一致。
备选：留在常用页并精简为一行三档、场景只负责预填——否决（用户明确选择了降级）：这样"场景"与"效果"仍是两个并列的一键入口。

**5. 用 tab 分「常用 | 专家」，而不是折叠区；纯翻译任务不分。**
tab 让两类内容各自成页、各自短；折叠区则把专家项又接在常用项后面，页面总长度不变，也没有位置放"这页有改动"的提示。专家页只有媒体任务（`isMediaTask`）才有；纯翻译任务只有「翻译重试次数」一个原本归在专家的候选项，把它放进常用页的「运行」，整个面板是单页、没有 tab。专家页里有偏离项时 tab 上显示小圆点。面板记住本次会话里最后停留的 tab；从场景弹层的「专家设置」打开则直达专家页。
备选：两个独立入口（「更多设置」「专家设置」两个面板）——否决：重复的页头 / 滚动区 / 摘要条，也让「这项在哪个面板」变成一个新的问题。

**6. 行式布局，说明收进 ⓘ。**
面板宽度只有 420px，现在每个字段是「标签在上、控件在下、说明在下面」，三行才一项。改为一行：左边标签 + ⓘ，右边控件；长 `FormDescription` 收进 ⓘ 提示（沿用工具栏 `ConfigItemHint` 的做法）；多行内容（提示词、命名模板）保持上下排。分组用 `SettingsGroup`（标题 + 分隔线），取代细小的全大写 `SectionTitle`。目标是常用页在 1024×700 的窗口里首屏就能看到前三组。
实测（tasks 7.3）：前两组整组在首屏，第三组的标题与首行也在、其余一次短滚动可达（「输出与保存」约 58% 可见，英文的「翻译与润色」约 71%），所以验收按"前两组整组 + 第三组至少一半"断言；不为塞进第三组去缩小字号或内边距。全局参考文稿由「标签 + 两行说明 + 通栏按钮」改成一行（说明收进 ⓘ），就是为了让前两组放得下。

**7. 依赖项按需出现，不适用的项不出现。**
语气词策略只在「AI 文本校正」开启时显示（只有 `correctionRunner` 读它）；角色数量与「写入字幕」只在角色分离开启时显示；命名模板只在选「自定义」时显示；`cloud` / `localCli` 引擎不显示识别策略，只留一行"当前引擎不使用识别策略"（沿用 `supportsTaskVadField` 对这两个引擎的先例，抽成同文件里的 `supportsOutcomeStrategy`）。隐藏只影响显示，不改任何已存的值。

**8. 工具栏：按「听 → 译 → 出」重排，标签改「输出」，不新增控件。**
现在「听」被「译」拦腰截断，而场景（会写入断句 / 校正默认值）排在翻译之后。改为 语音模型 → 视频语言 → 场景 → 断句与精修 ｜ 翻译成 → 翻译服务 → 词库 → 生成摘要 ｜ 输出，也符合"先选场景、再微调"的依赖顺序。组间用 1px 分隔线，实现为现有项上的边框而不是额外元素，不增加宽度；若零换行测试（1024 / 1440）不通过，则只保留顺序。标签新增 `configBar.output`，弹层内部的小节标题仍是 `configBar.format` / `configBar.style`。
备选：把「词库 + 生成摘要」合并为一个「翻译增强」控件以腾出宽度——放到第二期：牵动两个控件及其测试，而这次不需要这点宽度。

**9. 入口：页头、向导面板头、场景弹层脚注；回调 `onOpenSettings(tab?)`。**
任务页头的按钮由「高级选项」改为「更多设置」（有参考文稿时仍带提示点）；向导的 `PanelHeader`（配置面板）新增同名 `actions` 按钮，这是向导第一次有显式入口；场景弹层脚注提供「更多设置」与「专家设置」。`InlineConfigBar` 的 `onOpenAdvanced` 改为 `onOpenSettings(tab?)`，页面与向导各持有 `settingsTab` 状态。

**10. 命名。**
面板：「更多设置」（相对工具栏而言：工具栏是主要设置，这里是其余的；不叫"高级"，免得普通用户觉得与自己无关）；tab：「常用」「专家」；「字幕效果」→「识别策略」；档位里的「自定义」→「手动调节」；场景的「专家自定义」→「自定义」；工具栏「字幕格式」→「输出」。`tasks:advancedSettings`（「专家参数」，已无引用）删除；就绪提示、内封字幕对话框、首页提示里的路径改指「更多设置 › 常用」；设置页里对「字幕效果」档位的引用改为「识别策略」。

**11. 组件：改名并拆分。**
`AdvancedSheet.tsx` → `TaskSettingsSheet.tsx`（外壳：标题、摘要条、tab、滚动区），常用 / 专家各一个文件，`SettingsGroup`、`SettingRow` 放在 `renderer/components/tasks/settings/`。`FasterWhisperAdvancedFields` 与它的草稿输入逻辑原样保留（只换位置）。引用点只有任务页、向导和一个测试。`SubtitleFormatSelect.tsx` 之后没有引用者，删除。

**12. 数据层不动。**
不新增 / 删除 / 改名任何任务字段；`applyScenarioPreset`、`ALL_PRESET_FIELD_KEYS`、引擎映射与流水线原样不动。`scenarioPreset` 的含义不变（基础场景或 `custom`），变的只是界面怎么读它。
评审后有两处例外，都是修 `main` / v3.10.1 里就有的缺陷：`convertToCustomOutcome` 的旋钮列表抽成共用常量、旁边新增 `leaveCustomOutcome`，行为不变（决策 16）；下载流水线的 `buildSubmission` 加了一条与任务页相同的源字幕保存修正（决策 15）。

**13. 面板打开时焦点停在面板上，面板自身不画焦点环。（实现中补充）**
Radix 在对话框打开时聚焦第一个可 Tab 的元素。没有 tab 的单页（纯翻译任务）上，那是标签旁的 ⓘ；聚焦 ⓘ 会打开它的提示，于是面板一开就有一条提示压在首行上，而且提示是最上层，会吞掉第一次 Esc——面板要按两次才关（`speaker-pipeline` e2e 里「切完开关马上 Esc」就卡在这里）。所以用 `onOpenAutoFocus` 把焦点放到面板自身，Tab 仍从第一个控件开始；有 tab 与没 tab 的面板行为一致。面板不是控件，键盘打开时浏览器会给整块面板画一圈外框（Electron 里实测 `outline-style: auto`），因此面板加 `focus:outline-none`，里面的控件各自保留焦点环。
代价：带 tab 的面板打开时，焦点不在当前 tab 上，键盘用户要先按一次 Tab 才进入 tab 列表（Radix 默认直接落在 tab 上）。接受它，换来 Esc 一次即关、两种页面形态行为一致。
备选：只在无 tab 时把焦点停到面板上——否决：两套行为，而"先聚焦到 ⓘ"并不只可能发生在无 tab 的页；备选：让 ⓘ 不可 Tab——否决：键盘用户就读不到说明了。

**14. 每页从顶部开始：滚动区以当前 tab 为 key。（实现中补充）**
常用与专家是同一个面板的两页，共用一个滚动视口。在专家页滚动后切回常用，视口留在旧的偏移上，常用页的第一组被卷到上方，像是面板从中间打开。给 `ScrollArea` 加上 `key={activeTab}`，切页就换一个新视口，回到顶部。重建不丢任何东西：值与脏标记在表单里，不在页里（`shouldUnregister` 为 false，`TaskSettingsSheet.test.tsx` 锁定"切页不丢值，脏标记也在"）。不记住每页各自的滚动位置：两页内容差别大，回到上次位置的收益小，"打开就在顶部"是确定的。

**15. 「仅生成字幕」的源字幕保存方式：每个创建任务的入口按同一条规则修正，面板只改显示。（评审后补充）**
「保存源字幕文件」出厂是「不保存」（`noSave`）。「仅生成字幕」任务的源字幕就是交付物，停在 `noSave` 会让它以 `<视频名>_temp.srt` 落盘（`getSrtFileName` 的 `noSave` 分支）；主进程为了不丢交付物，对这种旧配置照常导出，只是名字不对。任务页一直有一个 effect 把它改成 `fileName`，面板对这类任务隐藏「不保存」并把残留值显示成「文件名」，向导没有那个 effect——面板显示「文件名」，提交的却是 `noSave`。实测（真 Electron + 本地假 ASR，向导里不改任何设置走「视频 → 原文字幕」）：完成后视频旁边是 `pauses_temp.srt`，五秒后仍在；显式设成 `fileName` 的对照组是 `pauses.srt`。v3.10.1 就是这样，不是本分支引入的；本分支新增的向导「更多设置」按钮只是让「显示 ≠ 实际」更容易被看到。
决定：规则只写一处，`types/sourceSrtSave.ts` 的 `correctedSourceSrtSaveOption(taskType, option)`（仅生成字幕且为 `noSave` / 空值时返回 `fileName`，否则返回 `undefined`；放在 `types/` 是因为渲染进程与主进程都要用，所以不带任何运行时依赖），四个入口按各自的方式使用：任务页改表单（`correctValue`，不记为默认值，`sync-task-defaults-on-edit` 的规则不变）；面板只改显示；向导与下载流水线**只改提交的配置，不改表单、不改已存的配置**。
为什么向导不改表单：任务页每种任务一页，页上的表单只会是这一种任务；向导的同一份表单会随「翻译」目标的开关在「仅生成」与「生成并翻译」之间来回切，若把 `fileName` 写进表单，切到翻译后源字幕就会多保存一份——带翻译的任务不保存源字幕才是默认。提交时再按当时的任务类型读一次，表单里的值始终是用户的选择（或出厂默认）。
备选：在主进程提交的唯一入口（`persistTaskSubmission`，已有 `withValidTranslateContent` 的先例）统一修正——否决：会让所有入口（包括自动化显式传入的值）的语义一起变，而问题只出在两个创建任务时没有替用户读这个字段的入口，各补一行比改全局语义小；以后再出现新入口，再考虑收到那里；备选：向导里加一个跟任务页一样的 effect——否决：理由同上，会污染切到翻译后的表单。
下载流水线（`main/helpers/videoDownload/pipeline.ts`，评审后一并修了）有同样的问题：配置来自 `defaultUserConfig` + 用户配置 + 配方，出厂的 `noSave` 没人改，`generateOnly` 的字幕落成 `<视频名>_temp.srt`。修在 `buildSubmission`（每个条目下载完成、真正组任务的那一刻），而不是 `resolveDownloadPipeline`（批次创建、用户确认配置的那一刻）：① 批次创建时就已存下的配置（升级前建的批次）一并修正；② 用户确认的配置指纹（`downloadPipelineKey`）不变，不会因此重新询问云端上传同意。下载到官方字幕、直接跳过听写的条目，`sourceOwned` 为 false，这个选项根本不被读取，改与不改没有区别。已经持久化的 `pending` 提交按设计原样重放（要保证幂等），不被改写。

**16. 从「手动调节」改选内置识别策略时，丢掉手动调节写进任务的值。（评审后补充）**
「手动调节」在进入时把被替换那一档的有效值（`maxContext`、`useVAD`、`reduceRepetition` 与 `TASK_VAD_FIELDS` 里的六个 VAD 字段）写进任务，供用户在此基础上微调（`convertToCustomOutcome`）；改选内置档位时，这些值原样留在表单里。内置档位自己决定 `maxContext` / `useVAD` / `reduceRepetition`，但 `resolveEffectiveSettings` 的 `withTaskVad` 让任务级 VAD 值对每一档都优先，于是留下的 VAD 值悄悄盖过档位自己的 VAD，档位名与实际参数对不上。实测：whisper 系拖过 VAD 滑块后切回「文字最准」，实际仍是 0.2 / 600，该档位本是 0.35 / 100；sherpa 系（funasr / qwen / fireRedAsr / parakeet）的档位只映射 VAD，只要点开过一次「手动调节」、一个滑块都没动，再改选「最干净最稳」，VAD 仍停在进入时那一档（均衡）的 0.5 / 250 / 100，而不是 0.65 / 400 / 150——各档之间对 VAD 不再有区别。这些值还会作为该任务页的默认值被记住，之后每个新任务都带着。`main` 与 v3.10.1 的 `AdvancedSheet` 里是同一段处理，不是本分支引入；评审时判断影响小、决定不修，用户随后要求修。
决定：`renderer/lib/scenarioPresets.ts` 新增 `leaveCustomOutcome(form, tier)`，把 `convertToCustomOutcome` 写入的那一组值全部置为 `undefined`，再设档位。两个函数共用同一张表（常量 `CUSTOM_OUTCOME_KNOB_KEYS`），不会一边加了字段另一边忘了；`undefined` 同时把它们从记住的任务默认值里去掉（`applyTaskDefaultsPatch` 的既有规则）。`ExpertSettings` 只在当前显示的档位是「手动调节」时调用它。
边界：① 内置档位之间切换仍只改档位——场景写进来的 VAD 值（如「会议访谈」的 0.35）照旧保留，那是场景的选择，不是手动调节留下的（`TaskSettingsSheet.test.tsx` 锁定）；② `scenarioPreset` 仍保持 `custom`，按钮继续显示「自定义」，这一步仍是单向的（见待办）；③ 以老快照没有 `subtitleOutcome`、靠旋钮反推出「手动调节」显示的任务，改选内置档位时同样清掉这组旋钮——用户明确选了某一档，就按那一档。
取舍：进了「手动调节」又退回内置档位的用户，调过的 VAD 滑块不会跟着回来。以前它们碰巧还在，再进「手动调节」能看到上次的值，但代价正是上面的错位；现在再进「手动调节」是从当前档位的值开始。

## Risks / Trade-offs

- [1024px 下加分隔线让工具栏换行] → 分隔线做成边框而非额外元素；`task-project-persistence` e2e（英文长标签下 1024 / 1440 核心控件同一行）与 `wizard-recovery` e2e（每个控件都在 inspector 内且可点击）把关；不通过就只保留顺序。
- [专家项更不显眼，需要的人找不到] → 专家 tab 上有偏离圆点；场景弹层脚注有直达专家页的「专家设置」；识别策略的症状语言说明与样例对比原样保留。
- [切 tab 丢值] → react-hook-form 默认不在卸载时丢值（`shouldUnregister` 为 false），并用测试锁定「切 tab 后值与脏标记不变」。
- [切换场景会重置已调整项，用户可能不知道] → 脚注明说「切换场景会重置它们」；「恢复为『X』」是同一个动作。
- [隐藏语气词策略等依赖项后，预设里写入的值看不见] → 这些值在对应功能关闭时本来就不生效；打开 AI 文本校正后控件出现，并显示已存的值。
- [e2e 选择器与文档大面积跟着改名] → Jest 与单元脚本随各提交同步更新，不留红的提交；e2e 选择器与文档站集中在最后一批（tasks 第 6 组）。中间几个提交里的 e2e 脚本仍是旧选择器——它们需要 Electron 与开发服务器，不在 pre-commit 的检查里——最后一批 `test(e2e)` 才把它们对齐并实跑。`dubbing-*` 两个 e2e 点的是配音面板自己的「高级选项」，不动。
- [「手动调节」会把场景变成「自定义」，与"已调整"是两种不同的状态] → 这是既有行为（`convertToCustomOutcome`），本次不改；脚注在该状态下说明"当前不再对应任何场景，选一个场景可重置"。
- [带 tab 的面板打开时焦点不在当前 tab 上] → 见决策 13：键盘用户多按一次 Tab，换来 Esc 一次即关、两种页面形态行为一致。
