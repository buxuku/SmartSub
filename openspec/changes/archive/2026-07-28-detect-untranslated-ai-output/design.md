# Design: detect-untranslated-ai-output

## D1: 文字系统优先于语言代码差异

语言代码不同不代表译文字符必须显著不同。系统识别源文本主文字系统，并与目标语言支持的文字系统比较；Latin→Latin 等同文字方向的相似结果不作为单条硬失败。Serbian 同时接受 Latin 与 Cyrillic。目标语言已知时不依赖源语言声明，因此 `auto` 仍可检测跨文字复制；明确的同语言代码继续豁免。

## D2: 强/弱证据分级

- 跨文字系统规范化精确复制且至少 2 个字母：强证据。
- 跨文字系统足够长且相似度 ≥ 0.9：强证据。
- 同文字系统精确/近似，以及短标题式或疑似专名的跨文字复制：弱证据。
- 数字、URL、邮箱、单字符、未知目标语言或明确同语言方向：无证据。

弱证据不会单独送修。标题/专名不是永久白名单：同批有至少 2 条强证据且强证据严格超过 1/3 时，跨文字精确复制弱证据可升级。源文本已经使用目标文字系统时不升级，保留 OpenAI、OK 等合理内容。

## D3: 修复闭环

批量结果先分类；问题数严格超过 1/3 时整批重试一次。之后逐条补翻，最多 3 次。每次补翻重新检查强证据；批次升级条目额外拒绝再次精确复制。批次升级条目本质仍是弱证据，补翻耗尽后回退批量模型原输出；由未翻译证据送修的条目中，只有强证据可写入失败占位。

## D4: 协议独立

回显协议继续负责 ID 对齐。未翻译语义校验在解析后独立执行，因此 `{src,tr}`、纯字符串、echo off 均采用相同证据规则；这显式修改了旧规范中“纯字符串仅条数+空值”的范围。
