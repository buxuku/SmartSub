# AI 字幕精修 · 技术设计

## Context

**现状**：成句逻辑分散在各引擎适配器内部并全部基于规则——builtin 走原生 token 路径（`tokensToTriples → clampTriplesToSpeechSegments → groupTokenCues → mergeShortCues → enforceMinDisplayDuration`，见 `main/helpers/subtitleSegmentation.ts`），faster-whisper 已开 `word_timestamps: true` 走 `composeWordCues`，云端听写在服务商返回词级时间戳时走同一词级管线；FunASR / Qwen3-ASR / FireRedASR / 本地 CLI 仅有段级输出，靠 `resplitSubtitleCues`（文本级 + 比例插值）兜底。引擎写完 SRT 后词级数据即被丢弃。规则断句的固有盲区：连接词吊行尾、犹豫停顿劈开数字/固定搭配、口头语碎片条——均需语义理解，调参不可解。

**可复用基建**：AI 翻译框架（`main/translate/services/ai.ts`：批量 JSON、回显锚定 D4、schema 属性上限 D8、错位整批重试 D7、单条修复、`batchConcurrency`、速率限制）；校对台批量润色（`ipcProofreadHandlers.ts` 的 `batchOptimizeSubtitles`：id→text 批处理、transcript 校对模式、重试、取消）；术语表注入（`main/glossary/`）；思考模式控制（`service/thinkingControl.ts`）。

**竞品参照**（源码核实 WEIFENG2333/VideoCaptioner）：断句遍用「原文不变、只插 `<br>`」协议 + difflib 相似度校验（≥0.96）+ diff 错误回喂的 agent loop（≤2 轮）；校正遍独立、id→text 批量、禁止合并拆分。其薄弱点：句子映射回词序列用相似度阈值 0.5 的滑动窗口模糊匹配；分窗按纯字数；护栏与语义混在一层。

## Goals / Non-Goals

**Goals:**

- 在转写后、翻译前提供可选的两遍式 AI 精修：语义断句（重构条边界、词级时间精度）+ 字幕校正（条内改文本）
- 全引擎覆盖：词级引擎精确模式，段级引擎近似模式
- 质量下限 = 现状：任何失败自动降级为规则断句结果，任务不失败
- 核心算法（协议编解码、校验器、offset 对齐、分窗）为零依赖纯函数，纳入现有 `tsc && node` 测试体系
- 复用 AI 服务商配置与既有批处理/锚定/术语表基建；校对台 AI 润色与校正遍共享同一服务

**Non-Goals:**

- 反思翻译（独立变更）；文稿提示通道（仅预留 prompt 注入点，不做 UI）
- 本地语义断句小模型（SaT/wtpsplit 免费档，后续演进）
- sherpa 系引擎的词级时间戳输出升级（近似模式先行）
- 实时/流式场景；校对台交互改版

## Decisions

### D1 · 独立管线阶段，不进引擎适配器

精修作为 `fileProcessor.processFile` 中转写之后的独立阶段，输入为「规则断句 cues + 词级时间轴（如有）」。替代方案：嵌入各引擎适配器（7 处重复、与转写耦合、无法统一降级）或挂在翻译阶段（职责混淆、纯转写任务享受不到）。独立阶段使 7 类引擎共享同一实现，且天然获得阶段级进度/取消/重试语义。

### D2 · 两遍分离：断句遍 verbatim，校正遍改字

断句遍要求逐字保持原文，才能把 LLM 输出**精确**对齐回词级时间轴；校正遍在条边界定型后只改文本、不动时间与条数。合并为一遍可省约一半 token，但校正会破坏 verbatim 性质，时间对齐从精确退化为模糊——拒绝。两遍各自可独立开关（仅开校正、仅开断句均合法）。

### D3 · 断句协议：verbatim + `<br>` 插标 + 校验反馈循环

LLM 收到分窗后的连续文本，返回插入 `<br>` 的同一文本。校验器（纯函数）验证：规范化等值（去空白后一致，容忍少量标点级差异并定位 diff）+ 逐段限长（CJK 字数 / 拉丁词数双上限，随任务断句设置派生）。不通过则把定位后的错误描述（改了哪、哪段超长）回喂 LLM 重试，上限 2 轮，耗尽降级。替代方案：让 LLM 返回断点索引数组（模型算不准索引，失败率高）；返回句子 JSON 数组（与 `<br>` 等价但输出更啰嗦、验证不更简单）。温度 0.1，思考模式默认按 provider 关闭。

### D4 · 对齐算法：规范化 offset 精确映射为主，模糊 diff 兜底

校验通过意味着拼回文本与原文规范化等值，因此在「规范化字符 offset → 词索引」映射表上一次线性扫描即可把每个 `<br>` 换算成词边界，新 cue 时间 = 首词 t0 → 末词 t1。仅当校验在容差内放行了轻微标点差异时，才对受影响窗口用 diff 对齐兜底。优于卡卡的全程滑动窗口模糊匹配（阈值 0.5，长视频易误配、开销大）。

### D5 · 分窗：按语音段边界，300–500 词/窗，窗间并发

窗口切点选真实 VAD/能量语音段间隙（builtin 路径已免费暴露；无语音段数据时按最大词间隔），目标 300–500 词。verbatim 协议下窗与窗互不影响，无需重叠，直接复用 `batchConcurrency` 并发与 provider 速率限制。

### D6 · 输入分档与词级时间轴传递

- **Tier 1 精确**：builtin（原生 token）、faster-whisper（segments[].words）、云端听写词级路径——引擎在现有成句前的 `TokenTriple[]` 基础上，将词级序列随转写结果传出（内存传递），并落盘 sidecar（工作目录 `<media>.words.json`）供任务重试续跑与后续能力（如校对台逐词定位）复用。
- **Tier 2 近似**：sherpa 系 / CLI——精修在规则 cues 的文本上重组（同一 `<br>` 协议，输入为按 cue 拼接的文本），新边界时间 = 命中 cue 的边界，句内切点用该 cue 内比例插值（复用 `resplitSubtitleCues` 的插值机制）。UI 与日志标注「时间轴近似」。

### D7 · 校正遍：泛化既有润色服务并增强

把 `batchOptimizeSubtitles` 的主进程逻辑抽为共享的字幕校正服务（id→text 批量、重试、取消），校对台润色与精修遍 B 共同调用，消除双份 prompt/批处理漂移。遍 B 相对现状增强：回显锚定（检测合并/滑移，对齐翻译框架 D4）、结构化输出 schema、术语参考注入——**只注入术语原文标准写法列表（不含译文、全量限量而非逐批命中）**：翻译术语块会指示模型替换为译文，用在校正上会把原文改写成译文（评审发现）；且误听变体（「库伯内提斯」）不会字面命中「Kubernetes」，全量参考才能让模型识别近似误听。低置信词标注（whisper token `p` 低于阈值的词列入「可能识别错」提示，仅 Tier 1 有）。失败批次保留原文。校正的默认约束沿用卡卡验证过的清单：禁止合并/拆分/改写结构，仅修错字、语气词、大小写、标点、公式与代码格式。

### D8 · 护栏与降级：语义归 LLM，物理归规则

遍 A 产出的 cues 仍依次过 `mergeShortCues`（回收碎片）与宽度/时长硬上限（超限走 `groupTokenCues` 同源的硬切回溯逻辑）、`enforceMinDisplayDuration`（最短可读）。降级矩阵：遍 A 校验耗尽/服务异常 → 保留规则断句 cues；遍 B 失败 → 保留遍 A（或规则）文本；整阶段异常 → 等同阶段未开启。取消经现有 AbortController 语义在窗口/批次边界响应。

### D9 · 配置、快照与后处理次序

任务级「字幕断句方式」由三态扩为四态：智能 / 不限制 / 固定宽度 / **AI 语义断句**（沿用现有字段承载，新增值不破坏旧快照）；「AI 字幕校正」独立布尔开关。两者默认关闭，Recipe / configSnapshot 自动承载，缺省即关闭（兼容既有 WorkItem 迁移机制，无需版本号变更）。后处理次序固定为：遍 A → 遍 B → 简繁转换/中文去标点（保证用户的简繁与去标点选项最终生效，校正遍补的标点不会与「去标点」冲突）。

**精修服务商选择（遍 A / 遍 B 共用一个选择器）**：字段取值为「跟随翻译服务」（默认）或显式指定某个 AI 服务商，候选池为已配置的 AI/LLM 类服务商（与 `getAiTranslationProviders` 同一分类，传统翻译 API 不在候选内）。

- **跟随翻译服务（默认）**：任务的翻译服务商为 AI 类型时，精修解析为同一服务商（同一密钥/模型/自定义参数），用户零额外配置；
- **显式指定**：可选任一已配置 AI 服务商，与翻译解耦（典型用法：翻译用大模型保质量，断句/校正用便宜小模型或本地 Ollama 省成本）；
- **不可解析场景**：翻译服务商为传统 API/免费翻译，或任务不含翻译（纯转写）时，「跟随」无法解析——向导在开启精修时即时校验并要求显式选择，避免运行时才失败；
- **快照语义**：configSnapshot / Recipe 保存「跟随」标记本身而非解析结果，复用配方时随新任务的翻译服务商重新解析，解析发生在任务启动时并把结果写入运行日志。

### D10 · 阶段状态与进度

新增独立阶段状态 `refineSubtitle`（loading / done / error + progress），沿用 `taskFileChange` 事件双写与任务页格子展示；进度按「窗口完成数 / 总窗口数」（遍 A）与「批次完成数 / 总批次数」（遍 B）合成。日志记录每窗校验重试次数与降级原因，便于诊断模型适配性。

## Risks / Trade-offs

- [LLM 改写原文导致断句遍失败率高（弱模型）] → 校验 + diff 反馈重试兜底；失败按窗降级不整段放弃；日志聚合失败率，文档给出推荐模型（DeepSeek / Qwen / GPT-4o-mini 级别即可胜任）。
- [长视频成本与时延（每遍约 2× 全文 token）] → 默认关闭、按需开启；分窗并发；进度可见可取消；Ollama 本地模型零成本路径写入文档。
- [近似模式时间轴精度受限于原 cue 边界] → UI/日志明示「近似」；不影响精确档；后续 sherpa token 输出升级为独立变更。
- [CJK/拉丁混排的限长判定歧义] → 按窗口主导语言选择限长维度（与卡卡同策略），物理护栏最终兜底，不会产出超宽条。
- [校正遍与回显锚定增加输出 token] → 锚定沿用翻译框架的可关闭设计（provider 级 `echoAnchoring`），默认开。
- [新阶段插入 fileProcessor 增加编排复杂度] → 阶段实现收敛在 `subtitleRefine/` 模块内，fileProcessor 仅增加一次调用点；核心算法纯函数化，编排层薄。

## Migration Plan

默认关闭、无破坏性：旧任务/旧 Recipe/旧配置快照缺省字段即视为未开启，行为与现版本完全一致；`refineSubtitle` 阶段状态对旧 WorkItem 不存在时 UI 不渲染该格子。回滚 = 关闭开关或移除阶段调用点，词级 sidecar 文件随临时目录清理机制回收。
