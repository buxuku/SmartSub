# Design: add-youdao-free-translator

## Context

**翻译契约。** `handleAPIBatchTranslation` 以 `batch.map((s) => s.content.join('\n'))` 调用翻译函数 `translator(string[], provider, from, to, { signal, glossaryEntries })`，要求返回等长数组；条数不等即判批次失败。因此条目内部的多行文本以 `\n` 保留在同一个字符串里，翻译函数必须自己处理。

**免费源现状。** `bingFree`、`googleFree` 在批内逐条串行请求，每条请求前 `acquire(rateKey, rateCfg, signal)`；错误统一写成 `<X> free translate failed (network): …`，以免被判成配置错误而中止任务；模块导出 `__test__`，由 `scripts/test-free-translators.cjs` 用 mock `axios` 离线测试。所有 `axios` 请求自动跟随 `proxyManager` 设置的全局代理 agent。

**`autoFree`。** `createFallbackTranslator(DEFAULT_FREE_FALLBACK_CHAIN)`：按链顺序尝试，源失败、条数不等或全空就换下一个，全部失败抛带 `(network)` 的聚合错误。批量大小、并发、请求间隔取 `autoFree` 自己的配置（默认 10 / 1 / 0.3 s），子源以 `{ ...proof, id: sourceId }` 调用，因此限速键为 `<源>:<源>`。

**迁移。** `providerManager` 用 `CURRENT_PROVIDER_VERSION`（现为 25）控制迁移：版本变化时才执行一次 `migrateProviders`，缺失的内置服务商按字段默认值补齐，`FREE_PROVIDER_IDS` 决定哪些服务商补齐默认请求间隔；全新安装走 `initializeDefaultProviders`，直接取字段默认值。

**证据（2026-10，单一出口 IP，国内网络，观测窗口约 25 分钟）。**

**约束。** SmartSub 为 MIT；Easydict 为 GPL-3.0。接口是非官方的，可能随时变化，也可能违反服务条款，沿用与 `bingFree`、`googleFree` 同级别的处理方式并如实披露。

## Goals / Non-Goals

**Goals:**

- 零配置免费路径的整集翻译耗时从分钟级降到秒级，并为必应故障提供第二个国内可直连的来源。
- 译文条数、顺序、格式（标签、对白、音符）可验证、可还原；失败时快速让位给回退链，而不是拖慢整批。
- 不引入新依赖、不改变其它免费源的请求形态，随时可从链里移除。

**Non-Goals:**

- 不把有道当作质量档，不宣传其译文质量；不支持术语表与上下文（与其它机翻一致）。
- 不做链级通用熔断、不改必应/谷歌/DeepLX 的行为与默认值、不做反检测或代理轮换。
- 不集成有道官方付费 API；不做「速度优先 / 质量优先」预设 UI（见开放问题 OQ5）。
- 本阶段不写代码。

## Decisions

### D1 · 协议实现与清洁室约束

采用与网页端一致的两步协议：先取会话密钥材料，再提交带签名的表单，响应为 AES-128-CBC 加密、base64url 编码的 JSON。解密结果里 `translateResult` 是段落数组，每个段落又是句子数组，句子带 `tgt`（译文）与 `src`（服务端回显的原文）；段末的 `tgt` 可能带 `\n`。仅依赖 Node 内置 `crypto` 与现有 `axios`，不新增依赖。

- 端点、表单字段、签名拼接与密钥派生细节 **以 `fanyi.youdao.com` 当前公开网页脚本为准**，实现时重新核对，PR 描述记录来源与日期；本文不复制签名常量。
- **清洁室**：Easydict 是调研阶段了解该协议的来源之一，但其许可证为 GPL-3.0。实现 MUST 自行编写，不复制其代码、注释、结构或变量命名；协议事实（端点、字段名、哈希与加密算法）视为互操作所需的事实，从官方网页脚本核对。
- 请求头沿用 `bingFree`/`googleFree` 同级别的浏览器式头（UA、`Referer`）和每进程随机生成一次的匿名标识 Cookie；不落盘。

备选：直接移植 Easydict 实现（许可证冲突，否决）；接入有道官方付费 API（需要用户申请凭据，违背「免配置」，另议）。

### D2 · 会话密钥生命周期

- 进程内存缓存，上限 30 分钟（实测 ≥15 min 不变；Easydict #762 说明密钥会「每隔一段时间」改变，周期未知，所以用上限兜住陈旧）。
- 单飞（single-flight）：缓存为空时并发调用共用同一个获取 Promise。
- 自愈：非空输入得到空结果（无 `translateResult`，或全部 `tgt` 为空）→ 强制刷新密钥，重试该请求一次；仍为空 → `(network)` 失败。这是因为签名或密钥失效时服务端返回 HTTP 200 + 空结果，没有错误码（实测）。
- 密钥获取不走 `acquire`（与 `bingFree` 的会话获取一致，频率极低）。
- 模块导出 `__test__.resetSession()` 便于测试。

备选：每次请求前重新取密钥（请求量翻倍，且实测并无必要）；只靠失败刷新、不设 TTL（陈旧只会在失败后才被发现，改成 TTL + 失败双保险）。

### D3 · 批量拼接与回显对齐

一次调用的处理顺序：

1. 语言映射与校验（D6），失败则不发任何请求。
2. 拆行与保护（D4），得到按条目顺序排列的待翻译段落；没有段落则直接返回原文，零请求（含不取密钥）。
3. 取会话密钥（D2）。
4. 按 5,000 字符切块（与 `bingFree`/`googleFree` 的 `MAX_TEXT_LENGTH` 一致；实测 12,031 字符单段可通过，但 Easydict #82 记录过长文本只译首句，故保守取值）。条数上限由应用层 `batchSize` 决定，这里不重复限制。
5. 每块以 `\n` 拼接，`acquire` 后 POST，解密并按段落汇总 `tgt` 与 `src`。
6. **对齐校验**：回显 `src` 经 NFKC 归一化并去除空白与标点后，须与对应输入段逐段相等且段数一致。NFKC 是必须的：实测服务端会把半角括号数字回显成全角（`(8)` → `（８）`），朴素比较会误报错位。
7. 校验失败 → 该块降级为逐段请求（每段一个请求，仍走 `acquire`，单段回显同样校验）；逐段仍失败 → 整个调用以 `(network)` 失败，不返回部分结果，由批级重试或回退链接手。
8. 还原（D4）与规范化（D5），按条目重组，返回与输入等长的数组。

实测批量输出与单条输出逐条一致（87/87），说明段落之间没有上下文串扰，拼接是安全的。

备选：逐条请求（实现最简单，单条模式也压测过，但请求量约 ×30，更像高频访问）；用自定义分隔符拼接（未测，担心分隔符被翻译或改写）。

### D4 · 字幕保护与还原

实测的问题：`<i>…</i>` 被翻成 `…</i>`，`<b><i>Run!</i></b>` 变成 `< b > <我>跑!< / i > < / b >`，`{\an8}` 被丢弃，`♪` 变 `♬` 或丢失，`- Hello.\n- Hi there.` 变 `- - - - - -你好。\n-嗨。`，`[door slams]` 变 `(砰地关上一扇门)`，符号行被改写（`...` → `．．．`）。所以必须在发送前剥离、译后还原。

按行处理（`\n` 拆行）：

1. **跳过**：不含 `\p{L}` 的行原样保留、不发送。
2. **词元化**：行首连续的 HTML 标签、ASS 块、♪/♫、对白破折号为前导串 L，行尾连续的 HTML 标签、ASS 块、♪/♫ 为尾部串 T，其余为正文 B；B 里的标签与 ASS 块直接移除。整行被 `[…]`、`(…)` 包裹时，去括号翻译内文，译后按原括号类型包回。
3. **配对**：对源行的 HTML 标签做栈配对（`<i>`/`<b>`/`<u>`/`<s>`/`<font>`），ASS 的 `\i`、`\b`、`\u`、`\s` 开关块按同样方式配对。若 L 或 T 中的某个标签，其配对对象在行中间被移除了，则这一对标签整体丢弃；源行本来就不配对（跨条目的斜体）则保持源行形态。`{\an8}`、`{\pos(…)}` 这类定位块不涉及配对，始终原位还原。原型实测里 `{\i1}Run{\i0} away` 会留下孤立的 `{\i1}`，这条规则就是为它设计的，实现时需用单测与一次实网各验证。
4. **分段**：对白破折号行、整行括号行、前一行已以句末标点（`.?!…。！？`，忽略其后的闭合引号与标签）结束的行各自成段；其余续行并入上一段，用一个空格连接（源语言为中日韩时直接连接）。实测 `He has been working here\nfor ten years.` 作为两段会被译成两个残句，合并后则是一个完整句子；该分段启发式本身尚未实测，需要在实现阶段用硬换行样例验证。
5. **还原**：每段译文加回首行的 L 与末行的 T，合并段输出为单行，独立段保持分行；条目译文 = 各段译文以 `\n` 连接。

| 源行                          | 发送                        | 还原                                     |
| ----------------------------- | --------------------------- | ---------------------------------------- |
| `<i>Don't look back.</i>`     | `Don't look back.`          | `<i>不要回头看。</i>`                    |
| `{\an8}Run!`                  | `Run!`                      | `{\an8}快跑！`                           |
| `♪ Never gonna give you up ♪` | `Never gonna give you up`   | `♪ … ♪`                                  |
| `- Hello.` / `- Hi there.`    | 两段 `Hello.` / `Hi there.` | 各行以 `- ` 开头                         |
| `[door slams]`                | `door slams`                | `[…]`                                    |
| `<i>Hello</i> there.`         | `Hello there.`              | 无标签（`<i>` 配对对象在句中，整对丢弃） |
| `...`、`10:30`、`♪`           | 不发送                      | 原样                                     |

已知限制：句中强调（`He said <i>never</i> again.`）会丢失；括号只处理整行包裹的情形，`(laughing) Stop it!` 这类前缀括号交给服务端，实测输出为 `（笑）住手！`。

备选：不保护（实测 5/101 行格式损坏，不可接受）；用占位符（如 `<0>`）包住标签一起翻译（未测，有被翻译或改写的风险，且会让回显校验更脆弱）。

### D5 · 中文目标译文规范化

仅当目标为简体或繁体中文：去掉段末 `\n`；紧邻汉字的半角 `, ? ! : ;` 转全角（实测 87 行里有道 5 行出现半角标点贴着汉字，必应 1 行）；全角数字 `０-９` 转半角（实测出现 `（８）`）。其它目标语言不做标点转换，日语等的行为未验证，留待后续。

备选：对整段译文做 NFKC（会把正确的全角 `，。！？` 也变成半角，否决）。

### D6 · 语言映射与支持范围

`supportedLanguage` 新增 `youdao` 列：简中 `zh-CHS`，繁中 `zh-CHT`，其余沿用通用码，未验证或不支持者显式 `null`；`TranslateProvider` 联合类型加上 `'youdao'`。源语言为空或 `auto` 时发送 `auto`（13 种支持的源语言实测可用）。

已实测的方向：英/日/韩/法/德/西/俄/葡/意/越/泰/印尼/阿 → 简中；简中 → 英/日/韩/法；英 → 繁中/日/韩/法/德/西；日/韩/法/德/西 → 英；日 → 韩；法 → 德。土耳其语（含 `auto` 检测）返回 `code` 40，不支持的方向返回 `code` 21，两者都转成包含 `not supported language` 的错误：该文案已被 `formatProviderError` 识别并本地化，且在 `autoFree` 里表现为「切换到下一源」。实现阶段对 `supportedLanguage` 全部条目逐项实测（每个方向一个请求，总量约百级），把结果固化进映射表。

### D7 · 限速、并发、超时与取值来源

- 每个翻译请求（含逐段降级、刷新后的重试）前 `acquire('youdaoFree:<providerId>', resolveRateLimitConfig(proof), signal)`。
- 独立服务商默认 `batchSize` 30、`batchConcurrency` 2、`requestInterval` 0.2 s、`windowMaxRequests` 0。上限依据：最小间隔把请求频率封在 5 req/s 以内，低于单条模式实测的 ≈10 req/s 与爬坡的 40 req/s。
- 作为 `autoFree` 子源时沿用 `autoFree` 的 10 / 1 / 0.3 s：整集 600 条约 60 个请求，受间隔限制约 18 s（推算）；独立默认值约 20 个请求、约 4 s（推算）；必应串行约 768 s（推算）。`autoFree` 默认值不动，必应与谷歌的请求形态不变。
- 请求超时 15 s（专用，短于全局 60 s）：实测 p99 ≤ 0.5 s，12 k 字符单段 0.6 s，首位源失效时不应让每个批次空等一分钟。
- 取消信号贯穿：`axios` 的 `signal`、`acquire` 的等待都会被中止，抛任务取消错误，不计入快速失效。

### D8 · 错误分类与有道专用快速失效

- HTTP 4xx/5xx（含 429、403）、网络错误、超时、解密或解析失败、刷新后仍为空：`Youdao free translate failed (network): <原因>`。429/403 时有道的行为未观测到（压测期间没有出现），按「未知」处理，不假设退避时长。
- 快速失效（熔断）：模块级状态，连续 3 次「请求级失败」→ 冷却 120 s，期间调用立即失败且不发请求；冷却结束放行一次探测，成功清零恢复，失败再冷却 120 s。请求级失败不含不支持语言与取消；逐段降级后仍失败计 1 次。任何一次成功清零计数。
- `youdaoFree.ts` 导出 `getYoudaoFreeAvailability()`，`fallback.ts` 的 `isSourceUnavailable` 据此在冷却期内以 info 级别「跳过」有道，避免每个批次都刷一条 warning。

为什么需要：有道排在链首，一旦失效或挂起，没有熔断时每个批次都要先付一次失败（最坏 15 s）才能到必应。链级通用熔断范围更大，列为非目标。

备选：不设熔断（最简单，但首位源失效时拖慢全体免费用户）；链级熔断（同样解决，但改变必应/谷歌行为，超出本变更）。

### D9 · `autoFree` 集成、默认顺序与迁移

- `fallback.ts` 的 `SOURCE_MAP` 加入 `youdaoFree`；`translationProvider.ts` 的 `TRANSLATOR_MAP` 加入 `youdaoFree`，`DEFAULT_FREE_FALLBACK_CHAIN` 改为 `['youdaoFree', 'bingFree', 'googleFree', 'deeplx']`；`types/provider.ts` 中 `autoFree.fallbackChain` 默认字符串与 `phFallbackChain` 占位同步；`ProviderForm.tsx` 的 `FREE_CHAIN_SOURCES` 加入 `youdaoFree`。
- 默认顺序是产品决策（OQ1），已确认取「有道在前」：免费档定位本就是草稿级，速度是最大的可感知收益；质量敏感的用户有 AI 翻译与校对台，也可在链编辑器里一键调整。
- 迁移：`CURRENT_PROVIDER_VERSION` 25 → 26。`migrateProviders` 已有「补齐缺失的内置服务商」机制，会自动加上 `youdaoFree`；`FREE_PROVIDER_IDS` 加入 `youdaoFree`；`autoFree.fallbackChain` 去空白后恰等于 `bingFree,googleFree,deeplx` 才改为新默认链，其余原样保留。迁移只在版本变化时运行一次，用户之后手动改回旧顺序不会被覆盖。这与仓库里「只升级仍等于旧默认值的字段」的既有做法一致（提示词、AI 批量参数）。
- 老版本容忍：旧版本 `fallback.ts` 遇到链里的未知 id 会记一条错误并继续下一个源，所以降级回旧版本时，已写入的新链不会让翻译失败。

### D10 · UI、i18n 与文档

- `types/provider.ts` 新增 `youdaoFree`（`group: 'free'`、`isAi: false`、无凭据字段）；`apiBatchFields` 增加可选的并发默认值参数（向后兼容），以便 `batchConcurrency` 默认 2。
- 资源：`common.json` 的 `provider.youdaoFree`（有道免费翻译 / Youdao (Free)）；`translateControl.json` 的 `chainSource.youdaoFree`、`batchSizeYoudaoFreeTips`，并更新 `batchSizeAutoFreeTips` 与 `fallbackChainTips` 里对「谁支持批量」的描述。
- 图标：先用 emoji 占位，不引入品牌 SVG，避免商标或授权问题（OQ2）。
- 文档：`free.md` 增加有道行、默认链顺序、「非官方接口、不承诺可用性、文本会发送至有道」的披露与替代建议，并更新页脚日期；`overview.md` 的「免费起步」、`subtitle-translation.md`、README 三语中「必应 / 谷歌」补上有道。服务商总数表述不变，因为内置免费源在文档里合并为一个条目。

### D11 · 测试策略

CI 与单测一律不访问真实网络，沿用 `scripts/test-free-translators.cjs` 的 mock `axios` 手法：

- 协议向量：用 Node `crypto` 对伪造的会话密钥材料自行加密一段响应，验证签名拼接与解密；
- 会话：缓存、TTL、单飞、空结果刷新重试、刷新后仍空；
- 批量：整批对齐、段数不等降级、回显不一致降级、逐段仍失败、5,000 字符拆块、全角回显不误判；
- 保护与还原：D4 表格逐行断言，外加配对丢弃、硬换行合并、全部行无需翻译时零请求；
- 规范化：半角转全角、全角数字、非中文目标不转换；
- 语言：映射表、`null` 不发请求、`code` 21/40；
- 限速、超时、取消、错误分类与熔断（用假时钟推进 120 s）；
- 链集成：`SOURCE_MAP`、默认顺序、冷却期跳过、聚合错误；迁移（旧默认被更新、自定义保留、幂等、性能字段不变）放进 `scripts/test-provider-fallback.ts`。

实网只做手动冒烟（见 tasks 的 Verification），总量控制在约 200 次请求内。

### D12 · 可观测性与日志隐私

沿用 `logMessage`。记录：`autoFree trying source: youdaoFree`、批次条数、HTTP 状态、对齐降级、密钥刷新、熔断进入与恢复。不记录字幕原文、译文、会话密钥、签名或完整响应体；错误信息里也不带原文。

## Risks / Trade-offs

- [非官方接口随时变化或失效] → 回退链兜底；会话密钥自愈；熔断避免拖慢；协议向量单测便于快速定位；文档如实披露「不承诺可用性」。Easydict 记录到的两次失效（2023-05、2024-12）各用了约 2–3 周修复；其后到 2026-10 未检索到新的失效，但检索并不完整，不能据此推断此后稳定。
- [限流行为未知：压测 0 信号 ≠ 无限流，仅单一出口 IP] → 默认频率 ≤5 req/s 且可调；429/403 立即按网络错误处理并触发熔断计数；不做规避。
- [质量低于必应，放首位会影响所有免费用户，无标点 ASR 风格长句更明显] → 草案接受这一取舍并在文档与提示里写明「速度优先」；OQ1 给出质量优先的替代；链编辑器可一键调整。
- [格式损坏] → D4 的保护与还原；已知限制（句中强调丢失）写入文档；实现阶段用硬换行与 ASS 配对样例补测。
- [合规：非官方接口可能违反服务条款] → 与既有 `bingFree`、`googleFree` 同级别做法；不绕过任何访问控制，不共享凭据，不做指纹伪装；可随时从链中移除；文档披露。
- [海外网络可达性与延迟未验证] → 15 s 超时 + 熔断 + 回退；欢迎海外用户反馈（OQ3）。
- [字幕文本发送至第三方服务器] → 文档披露（与必应、谷歌一致）。
- [对齐校验误判会放大请求量] → 降级最多 `batchSize` 个请求；日志记录降级次数，便于发现回显格式变化。
- [GPL 污染] → 清洁室实现与来源核对记录（D1）。
- [熔断与密钥缓存是进程级单例，多任务共享] → 符合预期：它们描述的是同一出口、同一服务的状态。

## Migration Plan

1. 随新版本发布：`CURRENT_PROVIDER_VERSION` 25 → 26；老用户补齐 `youdaoFree`，未自定义的旧默认链更新为新默认链；全新安装直接使用新默认。
2. 无需功能开关；默认顺序只在 `DEFAULT_FREE_FALLBACK_CHAIN` 与 `autoFree` 字段默认值两处（以及迁移的目标串），改顺序是一行改动。
3. 回滚：回退代码即可，旧版本对链里的未知源只记录一条错误并继续（见 D9）。如需让已迁移用户恢复旧链，再发一个版本（26 → 27），把恰为 `youdaoFree,bingFree,googleFree,deeplx` 的链改回 `bingFree,googleFree,deeplx`。
4. 文档与 README 随版本同步；`changelog.md` 按发布流程补充。
