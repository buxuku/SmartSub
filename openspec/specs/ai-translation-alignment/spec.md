# Spec: ai-translation-alignment

## Purpose

AI 批量翻译的条数、对齐与未翻译输出保证：按批次动态生成 JSON Schema 在解码层面锁死键集合；回显锚定（模型逐条返回 {src: 原文回显, tr: 译文}）确定性检测合并/滑移错位；独立的强/弱证据语义校验检测模型直接回传原文；失败分级（整批重试一次 → 单条定点补翻 → 单条标记失败）确保错位或明确未翻译结果不入库、单条失败不污染整批。源自 2026-07 调研与实测（详见 archive/2026-07-17-ai-translation-alignment 与 archive/2026-07-28-detect-untranslated-ai-output）。

## Requirements

### Requirement: 动态批次 Schema 约束

AI 批量翻译时，系统 SHALL 按当前批次的字幕 ID 动态生成 JSON Schema（每个 ID 为一个 required 属性，`additionalProperties: false`），并在支持结构化输出的渠道以 json_schema 模式随请求下发；service 层 MUST 优先使用调用方传入的动态 schema，未传入时保持现有静态 schema 行为。

#### Scenario: ollama 渠道使用动态 schema

- **WHEN** 通过 ollama 渠道以 json_schema 模式翻译一个包含 ID 1~20 的批次
- **THEN** 请求的 `format` 字段为包含且仅包含键 1~20（全部 required、禁止额外属性）的 JSON Schema，响应键集合与批次 ID 集合完全一致

#### Scenario: OpenAI 兼容渠道使用原生 response_format

- **WHEN** 通过 OpenAI 兼容渠道以 json_schema 模式翻译一个批次
- **THEN** 请求使用 `response_format: { type: 'json_schema', json_schema: { strict: true, schema } }`，其中 schema 为该批次动态生成

#### Scenario: 渠道不支持 json_schema 时降级

- **WHEN** 渠道对 json_schema 请求返回「不支持」类错误
- **THEN** 按既有回退链降级到 json_object 重试，翻译不中断

#### Scenario: 批次超过 schema 属性上限时自动拆分

- **WHEN** 用户配置的批量大小大于 100
- **THEN** 系统按不超过 100 条每批自动拆分后再翻译，每个子批次拥有独立的动态 schema

### Requirement: 回显锚定对齐校验

系统 SHALL 默认要求模型对每条字幕返回 `{src: 原文回显, tr: 译文}` 结构，并将回显 src 与该 ID 的真实原文做归一化相似度比对（阈值 0.75）；相似度不足或 tr 为空的条目 MUST 被标记为错位条目。provider SHALL 提供 `echoAnchoring` 开关（默认开启），关闭后系统 SHALL 退回非回显动态 schema，回显对齐校验仅执行条数与空值校验；独立的未翻译输出语义校验仍按下述强/弱证据规则执行。

#### Scenario: 回显全部匹配

- **WHEN** 模型返回的每条 src 与对应原文相似度 ≥ 0.75 且 tr 非空
- **THEN** 全部译文按 ID 入库，不触发修复

#### Scenario: 检测到合并滑移

- **WHEN** 模型将相邻两条原文合并翻译导致后续条目回显与真实原文不匹配
- **THEN** 所有相似度 < 0.75 的条目被标记为错位，进入定点修复流程，未受影响的条目正常入库

#### Scenario: 关闭回显锚定

- **WHEN** provider 的 `echoAnchoring` 设为 false
- **THEN** 请求使用 `{id: 译文}` 非回显 schema，回显对齐校验仅覆盖键集合一致与值非空；若源/目标语言明确，响应仍接受独立的未翻译输出语义校验

### Requirement: 解析器双形态兼容

响应解析器 SHALL 同时接受两种值形态：`{src, tr}` 对象（提取双字段供回显校验）与纯字符串（回显对齐降级为仅条数与空值校验）；两种形态混合出现时 MUST 逐条按各自形态处理，不得整批判失败。解析形态不得关闭独立的未翻译输出语义校验。

#### Scenario: 自定义提示词返回旧协议

- **WHEN** 用户自定义提示词使模型返回 `{id: 译文字符串}` 旧格式
- **THEN** 解析成功，跳过 src 回显比对并执行条数与空值校验；源/目标语言明确时继续执行独立的未翻译输出语义校验

#### Scenario: UI 提示更新自定义提示词

- **WHEN** 用户的 provider 配置了自定义系统提示词且其中不含 src/tr 协议约定
- **THEN** provider 设置界面展示提示，告知更新提示词可获得错位检测保护

### Requirement: 未翻译输出的强弱证据校验

系统 SHALL 在 AI 批量响应解析后、独立于回显协议形态执行未翻译输出语义校验。目标语言代码明确，且源语言代码未知（含 `auto`）或与目标语言不同时启用；源/目标语言代码明确相同时仍须豁免。系统 MUST 将证据分为：

- **强证据**：去除字幕标记、URL 与邮箱后，源文主文字系统与目标语言预期文字系统不兼容，且译文为规范化精确复制（至少 2 个字母），或足够长文本的高相似复制；
- **弱证据**：同文字系统的精确/高相似结果，或短标题式、疑似专名的跨文字精确结果；
- **无证据**：单字符、纯数字、纯 URL/邮箱、目标语言不明确、同语言代码或相似度不足。

强证据条目 MUST 可单独进入修复。弱证据 MUST NOT 单独触发定点补翻或补翻耗尽后的硬失败。当同批至少 2 条强证据且强证据数严格超过批次的 1/3 时，系统 MAY 将同批跨文字系统的精确复制弱证据升级为待修复；本身已使用目标文字系统的专名/短内容以及纯数字、URL、邮箱 MUST 不参与升级。升级条目补翻耗尽时 MUST 回退保留批量模型的原输出；在未翻译证据路径中，只有强证据条目允许写入失败占位符。

#### Scenario: 跨文字短句原样返回

- **WHEN** 源语言为中文、目标语言为英语，模型对「继续向前跑」逐字返回原文
- **THEN** 该条作为跨文字系统精确复制强证据进入修复，不受长文本阈值限制

#### Scenario: Issue 283 整批原样返回

- **WHEN** 一个批次包含 issue #283 的 10 条中文且旧字符串协议响应逐条返回相同中文
- **THEN** 10 条均被标记为未翻译，整批重试一次；重试后仍复制原文则逐条定点补翻

#### Scenario: 自动识别源语言仍检测跨文字复制

- **WHEN** 源语言为 `auto`、目标语言为英语，模型将中文原文逐字放入译文字段
- **THEN** 系统根据源文本文字系统与已知目标语言判定强证据，并进入相同的重试与补翻流程

#### Scenario: 同文字系统合法近似翻译

- **WHEN** 西班牙语「Este problema es importante」译为葡萄牙语「Este problema é importante」
- **THEN** 该结果至多记录为弱证据，不触发补翻或失败标记

#### Scenario: 同文字系统合法同文

- **WHEN** 克罗地亚语文本翻译为塞尔维亚语后合法保持相同拉丁文字
- **THEN** 该结果至多记录为弱证据，不触发补翻或失败标记

#### Scenario: 非语言与合理保留内容

- **WHEN** 译文与原文相同但内容为纯数字、URL、邮箱、单字符，或原文已使用目标语言文字系统的专名
- **THEN** 该条不作为强证据，且不因其他条目的批次证据被升级

### Requirement: 失败分级与单条定点补翻

批次校验失败时系统 SHALL 分级处理：响应不可解析，或错位、空值及强/升级后的未翻译条目总数严格超过批次的 1/3 时整批重试一次；问题条目数不超过 1/3 时对每个问题条目执行单条定点补翻（携带前后各 2 条原文与已译文作为上下文、单键 schema 锁定输出、最多 3 次）。比例判断 MUST 使用数学上的 `problemCount * 3 > batchSize`，不得因向上取整漏掉 10 条中的 4 条。每次补翻结果 MUST 再次执行相同强证据校验；由批次证据升级的精确复制还 MUST 拒绝再次逐字复制。错位、空值或强证据条目补翻仍失败时 MUST 单独标记为翻译失败，同批次其余译文 MUST 正常入库；批次升级的弱证据条目补翻耗尽时 MUST 恢复其原输出，不得进入失败占位路径。

#### Scenario: 个别空值触发定点补翻

- **WHEN** 批次响应中 1 条译文为空串、其余正常
- **THEN** 仅对该条发起带上下文的单条补翻请求，成功后与其余译文一并入库，无整批重试

#### Scenario: 大面积错位触发整批重试

- **WHEN** 批次中超过 1/3 的条目回显不匹配
- **THEN** 整批重试一次；重试后仍有个别问题条目则转入单条补翻

#### Scenario: 10 条中 4 条触发整批重试

- **WHEN** 一个 10 条批次有 4 条被标记为错位、空值或强未翻译证据
- **THEN** 系统判定 4/10 严格超过 1/3，并整批重试一次

#### Scenario: 补翻耗尽后局部失败

- **WHEN** 某强证据条目单条补翻 3 次均失败
- **THEN** 仅该条目标记为翻译失败（targetContent 含失败标记），批次其余条目译文正常写入结果

#### Scenario: 升级专名补翻耗尽

- **WHEN** 批次强证据将 `OpenAI` 这类精确复制弱证据升级，但其 3 次补翻仍正确返回 `OpenAI`
- **THEN** 系统保留批量模型原先输出的 `OpenAI`，不得用翻译失败占位符覆盖

### Requirement: 默认提示词升级与迁移

默认系统提示词 SHALL 升级为 {src,tr} 回显协议（含输入输出示例），旧默认提示词 MUST 追加进历史提示词列表；provider 配置版本迁移时仍在使用任一历史默认提示词的用户 SHALL 自动升级为新默认值，自定义过提示词的用户 MUST 保留原值。

#### Scenario: 未修改默认提示词的用户自动升级

- **WHEN** 用户的 systemPrompt 与任一历史默认提示词一致且触发 provider 版本迁移
- **THEN** systemPrompt 更新为新的 {src,tr} 协议默认值

#### Scenario: 自定义提示词用户保留原值

- **WHEN** 用户的 systemPrompt 与所有历史默认值均不一致
- **THEN** 迁移后 systemPrompt 保持用户自定义内容不变
