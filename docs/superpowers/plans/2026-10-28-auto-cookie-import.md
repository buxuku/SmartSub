# 自动识别站点 Cookie 实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. 用户已授权直接实施，在新分支中保留之前的修复。

**Goal:** 从浏览器或 cookies.txt 一次导入，识别下载站点、按站点保存，并按下载链接自动使用。

**Architecture:** 扩展现有站点目录和每站点档案；浏览器只提取一次，批量分类并一次提交元数据。保留原有自定义档案与单站点导入入口，原始全浏览器文件仅存在于私有临时目录。

**Tech Stack:** Electron、TypeScript、React、yt-dlp、现有脚本测试及 Jest。

**Spec:** 本文以下已获授权的范围，以及当前会话用户选择的推荐方案。

## 约束和产品行为

- 自动导入只保存站点目录和已有自定义站点覆盖的 Cookie；目录不等同于下载引擎的全部站点列表，界面明确列出自动识别范围。
- 默认展示已导入的站点，未导入站点放在可展开列表；手动域名、单站点文件和粘贴作为高级入口。
- Chromium 可选择真实用户档案，默认最近使用的档案，排除 Storage/ext 内部 Cookie 数据库；保留 Firefox/Safari 提取兼容性。
- 同一站点再次导入整体替换，不混合不同浏览器账号；未发现的站点保留旧档案，界面明确结果。提取或批量保存失败时旧数据不变。
- 显示站点、数量、浏览器/档案来源、导入时间；“已导入”不代表已登录或可以下载。仅在有可靠关键 Cookie 或全部 Cookie 过期时提示过期。
- 全量 Cookie 绝不交给 lux；下载时再做站点过滤。已有档案无需用户重新导入。
- 不纳入未合并的抖音提取器补丁，403 不作为 Cookie 确定失效的证据。
