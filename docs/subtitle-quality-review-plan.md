# 智能质检与问题优先校对

分支：`feat/subtitle-quality-review`。目标：减少可交付字幕的人工校对时间。

## 已确认的产品决策

- 在现有校对台内增加问题模式；首次保留全部字幕，恢复同一文件的检查位置。
- 本地自动检查，AI 修改由用户触发。默认少而准，低置信语音和重叠列入更多提示。
- 剩余问题显示数量，不新增完成确认弹窗；保存失败仍阻止完成。
- 不做全文 AI 检查、新的局部音频重识别、自动批量采纳、跨设备同步。

## 设计规格

目的：在相同工作台完成发现、试听、编辑、检查下一处。采用工业工具工作台风格。
沿用 Studio Blue：浅色品牌蓝 #1668dc，深色品牌蓝 #409cff，深色画布 #101114、面板 #1b1e23；警告/失败/成功沿用主题语义变量。
字体沿用 Segoe UI / PingFang SC / Microsoft YaHei 系统栈，时间码使用 SF Mono / Cascadia Code；这是现有设计系统对通用 UI 技能字体建议的覆盖。
保留左右双栏，问题视图替换右侧列表；纯字幕占满宽度。紧凑列表与背景色阶，正文沿用字号档位，解释至少 12px。Lucide 图标加文字表达状态。

## 交互

- 全部字幕 / 建议检查切换，类型、状态、更多提示和时间/优先排序；同句问题合并展示，无对应字幕的疑点独立显示。
- 点击只定位，试听播放前后各一秒并自动暂停，可循环。播放进度不改变正在检查的对象。
- 原文/译文内联编辑；查看上下文显示前后两句。修复后条目保持原位，主动进入下一处。
- 确认无误、暂时跳过、恢复待检查，所有动作可撤销。检查结束提供跳过项、全部字幕及完成入口。
- AI 原文/译文动作明确；重翻、精简和已有复核建议均展示差异、确认采纳。缺少服务时可继续手动改。
- 无字幕空档可手动补一句，确认有效时段后插入；不自动重叠。

## 规则

翻译失败/缺失复用已有判断；语音复核复用已有证据；阅读速度沿用中文 8、其他 20 CPS；超出媒体 100ms 默认提示，重叠超过 100ms 放更多提示；源词命中且当前及相邻译文未出现词库指定译法时提示。
词库优先级、NFKC、大小写及拉丁词边界沿用已有实现。没有数据不冒充检查通过。部分检查失败保留其他结果和重试。

## 实现

统一 QualityIssue / QualityReviewState；按时间、类型和证据关联，禁止只依赖会重新编号的字幕 ID。
检查分批执行，200ms 防抖、取消过期结果、复用未变字幕检测。复用编辑行、波形、AI diff、历史及即时草稿。
进度使用独立原子文件与 qualityReview:read/save IPC，草稿加入可选状态；旧字幕/sidecar/草稿兼容。
修改、确认和补字幕进入统一撤销历史。全部当前版本保存成功后才显示已保存；仅进度变更不重写字幕。

## 验收

规则及误报边界、连续输入无跳动、试听范围、跳过回找、无字幕空档；保存失败、异步迟到、合并拆分、撤销、重启/强杀恢复。
真实 Electron 浅/深色、中文/英文、1024/1440、字幕/音频/视频与键盘截图。
一万行与 500 词条：首次检查目标两秒内，检查期间输入 P95 小于 100ms（报告实际环境）。类型、i18n、相关单元与端到端回归、生产构建。
产品目标：对相同人工标注素材，问题修复完整度不下降，中位处理耗时减少至少 30%；需后续用户研究验证。

### 性能实测

一万行字幕、500 词条、产生一万个术语提示，macOS Apple Silicon / Node 22.22.3 / Electron 30：

| 指标                                                         | 实测   | 目标     |
| ------------------------------------------------------------ | ------ | -------- |
| 从打开文件到初次检查显示完成（含文件加载、200ms 防抖和渲染） | 1087ms | < 2000ms |
| 手动重新检查完成（复用未变行）                               | 311ms  | < 2000ms |
| 连续输入至下一帧 P95（16 次）                                | 48ms   | < 100ms  |

性能脚本：`npm run test:e2e:quality-performance`。这是本机合成素材的回归基线，不能推断所有设备或真实素材的表现。人工处理时间减少 30% 仍需同素材对照用户研究，未宣称已经验证。

## 评审修复

- 撤销 / 重做处理状态时保留当前补字幕表单；读取进度重试成功后，恢复草稿及本次编辑优先于旧进度。
- 当前检查结果完整展示；已消失问题仅保留最多 5000 条历史缓存。持久化问题缓存最多 50000 条、8 Mi 字符，优先保留当前问题及有用户记录的问题；确认决定与补字幕文字独立保留。重新打开会重新生成当前问题，用户决定仍按证据匹配。无效的可选检查元数据不再导致整份字幕恢复草稿丢失。
- 证据使用实际翻译失败状态，不使用 SRT 无法保存的临时成功状态；相同文字与时间重新打开后保留确认。
- AI 重试保留原文 / 译文及操作类型。设置面板明确选择提示词对象，两类提示词均加载且分别保存、重置。
- 新增测试覆盖确认后输入再撤销、读取重试与恢复/并发编辑、60000 条生成问题保存、超限与损坏元数据草稿恢复、SRT 往返、原文错误/过期建议重试和提示词持久化。
- 修复后类型、i18n、生产构建及 48 组 / 477 项全量测试通过；质检与 AI 专项通过；真实 Electron 验证原文自定义提示词、失败重试和采纳均保持原文字段，译文不被改写。
