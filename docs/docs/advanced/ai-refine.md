# AI 字幕精修（语义断句与校正）

规则断句只认停顿、标点和字数，所以会出现「连接词吊在行尾」「犹豫停顿把数字劈成两半」这类靠调参数修不掉的问题。AI 字幕精修在转写完成之后、翻译之前，用大模型补上语义这一层：

- **AI 语义断句**：把词级时间轴上的转写按语义重新组句。断点由大模型决定，时间仍取每个词的真实时间戳——`一共花了三……十五天` 不再被停顿切成「花了三｜十五天」。
- **AI 字幕校正**：逐批修正同音字/错别字、删除「呃、嗯」等语气词、规范标点与英文大小写；不改变字幕条数与时间轴，失败的条目保留原文。

两项都是任务级可选功能，默认关闭；翻译质量也会连带受益——送去翻译的每一条都是完整语义单元。

## 开启方式

1. 任务向导 → 配置栏 → **断句与精修** → 断句方式选择 **AI 语义断句**
2. 如需文本校正，在同一弹层打开 **AI 文本校正** 开关（两项可独立使用）
3. 选择 **精修服务商**：默认「跟随翻译服务」——翻译选的是 AI 服务商（DeepSeek、通义千问、Ollama 等）时零额外配置；也可以显式指定另一个服务商，比如翻译用大模型、精修用本地小模型省成本。想给精修单独指定本地模型，见[下一节](#用本地-ollama-单独配置精修模型)。

## 用本地 Ollama 单独配置精修模型

「精修服务商」列出的是已添加的 AI 类翻译服务配置，不是 Ollama 本机模型列表。直接选择现有的「Ollama」项，会使用该项在「翻译」页面配置的模型。如果翻译和精修需要用不同的模型，保留现有配置，另建一个指向本机 Ollama 的服务：

1. 确认本机 Ollama 正在运行，用 `ollama list` 查看已安装的模型及标签。
2. 在左侧「翻译」页面点击服务商列表顶部的「**+**」（添加自定义服务），填写一个好区分的服务商名称（例如 `Ollama 精修`）。「**API 地址**」填 `http://localhost:11434/v1`，这是 [Ollama 的 OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)，不要填内置 Ollama 配置项使用的 `/api/chat`。
3. 添加后在这个服务的配置页中，API Key 填占位值 `ollama`（本机 Ollama 不校验该值），「**模型名称**」填 `ollama list` 里的完整名称，例如 `qwen2.5:7b`。本地模型可先把「**批次并发数**」设为 `1`、「**批量翻译数量**」设为 `10`（新建自定义服务默认分别为 2 和 20，内置 Ollama 配置默认分别为 1 和 10）。可用「**测试翻译**」确认这个服务能连接并使用该模型。
4. 回到任务的「**断句与精修**」，在「**精修服务商**」明确选择 `Ollama 精修`，不要选「跟随翻译服务」。任务的翻译服务仍可选择原来的 Ollama 配置，两个模型互不影响。

:::caution 上下文长度

内置 Ollama 配置通过原生接口发送 `num_ctx: 8192`，但走 OpenAI 兼容接口时，SmartSub 无法在单次请求中设置上下文长度。Ollama 的默认上下文长度会随版本、硬件和服务配置而异。断句窗口较长，校验重试还会带上前一次的输出；上下文不足时，文本可能被截断，校验仍不通过的窗口会回退为规则断句。

「测试翻译」只能确认基本连通性，建议再用有代表性的音频跑一次任务，在日志的 `AI segmentation done` 中查看 `degradedWindows`。大于 0 表示有窗口回退，不一定是上下文不足，先查看[行为边界](#行为边界)中的降级原因。

如果确认需要更大的上下文，可以创建一个专供精修使用的标签。例如将下面两行保存为 `Modelfile`：

```text
FROM qwen2.5:7b
PARAMETER num_ctx 8192
```

执行 `ollama create qwen2.5-7b-8k -f Modelfile`，再把 `qwen2.5-7b-8k` 填入「模型名称」。也可以在启动 Ollama 服务时设置 `OLLAMA_CONTEXT_LENGTH`，但该设置会影响服务端的默认上下文。更长的上下文需要更多内存或显存，详见 [Ollama 上下文长度指南](https://docs.ollama.com/context-length)。

:::

只要使用本机运行的模型，精修不会产生云端 API 费用，文本也不需要发给云端服务。

## 服务商与模型建议

- 断句任务本身很简单（在原文里决定断点位置），**7B–32B 级别的模型即可**；DeepSeek、通义千问、GPT-4o-mini 级别的在线模型表现稳定
- 校正任务受益于更强的模型（上下文改错），推荐与翻译同级别的模型
- 模型回显原文时常丢标点、改大小写、偶尔错一两个字：这类细小出入（与转写相比不超过 4%）会被接受，字幕文字始终取自转写本身，不会带入模型的改动
- 弱模型改写得更多：系统会带错误反馈重试两轮，并保留各轮中最好的一次；仍不可用才让该段自动回退规则断句——**最坏结果等于不开启，不会更差**

## Token 消耗

- 语义断句：约消耗全文 2 倍 token（模型需要回显插标后的原文）
- 字幕校正：约消耗全文 2 倍 token（回显锚定用于检测错位）
- 一小时视频的转写文本约 8–12k 字，两遍全开在 DeepSeek 上的成本通常在几分钱量级

## 并发与请求间隔

AI 语义断句（按窗口）和 AI 文本校正（按批次）都读取精修服务商的这两项配置，与翻译共用同一份。在该服务商的配置页调整即可，各项的含义见[翻译服务配置指南](/guides/translation/overview)：

- **批次并发数**：同时进行的请求数，最多 10，没填时按 1 处理；新建服务商的默认值因服务商而异（例如 DeepSeek 和新建自定义服务为 2，内置 Ollama 配置为 1）。断句按窗口并行（一个窗口约 300–500 词），校正按批次并行（每批的条数取服务商的「批量翻译数量」）；窗口或批次比并发数少时，实际并发取较小值。长视频调高后精修会明显变快，但需要服务商配额支持，可能触发限流；本地模型受显存限制，通常保持 1–2
- **请求间隔**：相邻两个窗口（或批次）开始发送之间至少隔开的秒数，用来避开限流。开启并发时它只错开开始发送的时间，已经发出的请求仍然同时进行
- 想确认实际生效的值：在任务日志里搜索 `AI segmentation windows=`（断句）和 `Correction batches=`（校正），行内的 `concurrency=N` 就是本次使用的并发数

校对页的「全文 AI 优化」与文本校正共用同一个实现，同样按这两项配置发送请求。

## 引擎适配说明

| 转写引擎                                              | 断句时间轴                         |
| ----------------------------------------------------- | ---------------------------------- |
| 内置 whisper.cpp                                      | 词级精确（真实词时间戳）           |
| faster-whisper                                        | 词级精确                           |
| 云端听写（whisper-1 等词级服务商）                    | 词级精确                           |
| FunASR / Qwen3-ASR / FireRedASR / Parakeet / 本地 CLI | 近似（条内按比例插值），界面会提示 |

内置引擎与 faster-whisper 还会把低置信度的词标注给校正模型（「这些词可能识别错」），定点修正更有把握。

## 行为边界

- 精修只作用于**本轮 ASR 转写产物**：内封字幕提取、配对字幕、用户导入的字幕不会被重新断句
- 简繁转换与「中文去标点」在精修之后执行，你的字形与标点选项始终最终生效
- 服务不可达、密钥无效、校验重试耗尽：自动降级为规则断句并记录日志，任务不失败
- 每次请求最多等待 5 分钟；某个窗口已经有可用答案后，后续重试限时更短，重试失败也不会丢掉已有答案
- 想确认断句有没有生效：在任务日志里搜索 `AI segmentation`。结尾的 `degradedWindows=N` 是回退规则断句的窗口数，每个降级窗口前都有一行原因（`content differs` 模型改写过多、`request failed` 请求失败或超时、`could not be aligned` 无法对齐）；`copy drifted ... re-anchored` 表示模型有细小出入、已按转写原文校正后采用。`validation failed` 里的 `similarity` 是原文与模型副本的字母数字相似度，`<75%` 表示整段被改写、不再逐词比对；`content differs` 之后会带上第一处具体差异，例如 `"…want to [talk] about…" was changed to "[speak]"`，方括号里是原文被改动的词和模型写的词
- 任务配置快照与配方（Recipe）会记录精修设置；「跟随翻译服务」保存的是跟随语义本身，换任务时随新的翻译服务商重新解析
