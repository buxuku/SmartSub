# SmartSub 全软件 UI / UX 评估

日期：2026-09-16。源码基线：`1fba8b192fcdecd7837ba0d39daf8e46b6abf110`。

本报告覆盖布局、视觉、交互、操作链路、理解成本、上手成本和专业使用效率。交付为分析与改进建议，本轮未修改业务代码。

## 1. 结论与证据边界

当前产品已经有较完整的媒体工作台基础：统一外壳、深浅主题、任务配方、批处理、校对、配音、合成、资源总览、命令面板和任务恢复。最有价值的下一步是让这些能力遵循一致的任务与状态规则，让用户清楚知道“当前处理什么、用什么配置、是否保存、下一步是什么”。

最先应处理的是保存可靠性和状态可信度，其次是配置与任务之间的往返成本，再统一工具箱、编辑器和设置页的布局与控件规范。单纯扩大字号、增加阴影或更换配色，无法解决这些主要问题。

证据分为三类：

| 标记 | 含义 | 使用限制 |
| --- | --- | --- |
| C | 当前源码可确认的结构或行为 | 涉及实际触发结果时仍需回归验证；不能据此宣称做过实机测试 |
| V | 仓库现有截图中的视觉观察 | `docs/static/img/v3/` 为文档截图，部分显示 v3.5.0、7 月日期；不能代表当前所有状态 |
| H | 基于结构提出的风险或设计假设 | 需要窗口实测、任务测试或用户观察，不能当作已复现缺陷 |

本次直接查看了启动台、任务向导、校对、配音、合成、下载、引擎总览、声音总览、词库、设置的现有截图，并复核相关源码。原任务中的桌面与浏览器连接未成功；本次未进行当前 Electron 窗口的点击、截图、屏幕阅读器或性能测试。没有给出缺乏测量依据的体验总分、对比度达标结论或转化提升百分比。

优先级定义：P0 为工作丢失或保存误报；P1 为结果错误、状态误导、主流程阻碍；P2 为效率、发现性与一致性；P3 为依赖真实需求验证的增强能力。这里是改进排期建议，不等同于线上事故等级。

### 1.1 应保留的已有能力

- 保留 Studio Blue 品牌、64px 导航和工作台布局基础。它们是已有设计决策，见 [v3 设计方案](ui-v3-proposal/README.md)，不建议为本轮评估整体推翻。
- 任务完成后已经能携带字幕和源视频进入校对、配音、合成，见 [CompletionBanner](../renderer/components/tasks/CompletionBanner.tsx)。优化重点是统一上下文与结果反馈。
- 已有配音会话恢复、任务配置快照、校对批次保存。需要明确各自的保存边界，不能笼统评价为“没有恢复能力”。
- 校对和配音列表已有虚拟化；AI 批量优化已有原文对照、结果选择和应用操作，不应重复建设这些基础能力。
- 引擎、翻译、声音已有总览与推荐路径；新手引导已有示例任务与暂停后恢复入口；下载已有携带官方字幕进入后续任务的能力。

### 1.2 优先处理的问题

| ID | 优先级 / 证据 | 具体问题与用户影响 | 推荐处理 |
| --- | --- | --- | --- |
| R01 | P0 / C | 校对编辑器只对页内返回和 `beforeunload` 做未保存保护。侧栏通过 Next Link 切页，未见统一路由守卫；未保存编辑存在被卸载丢失的路径 | 建立统一离开保护；保存失败留在原页；草稿恢复作为第二层保护 |
| R02 | P0 / C | 校对批次保存函数末尾无条件返回 `true`；IPC 返回 `success: false` 时仍会触发“任务已保存”提示 | 校验创建和更新响应；错误展示可重试；保存状态只由成功响应推进 |
| R03 | P1 / C | 首页缺少模型或服务时先跳配置页，尚未收集拖入文件；返回后用户需要重新选择文件和任务入口 | 先保存任务意图与输入，再进入配置；配置完成回到同一草稿 |
| R04 | P1 / C | 底栏无条件渲染“引擎就绪”，指示点主要取决于加速徽章，不等价于模型、运行时或服务真正可用 | 分开表达引擎、模型、服务和 GPU 状态，显示检测中、缺依赖、可用或失败 |

| R08 | P1 / C+H | 新任务向导输入与配对保存在组件状态，跨页交接键一次性消费；启动前未见完整草稿恢复路径 | 在任务创建前保存文件、目标、配对和局部配置，切页后可恢复 |

| R10 | P2 / C+H | 工具箱普遍使用 `p-6 / gap-6 / rounded-xl / w-80 shrink-0`，和主工作台密度不同；英文界面仍含大量硬编码中文 | 统一工具页面结构和国际化；在最小窗口验证换行、滚动、主操作可见性 |

## 2. 用户与操作链路

### 2.1 三类用户需要不同程度的配置暴露

| 用户 | 首要目标 | 当前认知负担 | 设计重点 |
| --- | --- | --- | --- |
| 偶尔处理视频的人 | 拿到可用字幕或译制视频 | 不理解引擎、模型、服务商、配方、软字幕等概念之间的关系 | 先选择结果，按所需能力提供一个推荐配置，隐藏暂时无关参数 |
| 批量制作内容的人 | 连续处理多份素材，发现失败并续跑 | 在不同页确认配置、保存状态与输出文件 | 固定任务上下文、批量选择、按阶段重试、明确产物版本 |
| 专业字幕与配音用户 | 精确修订、检查质量、稳定交付 | 频繁打开浮层、滚动属性区、检查字幕与音频时长 | 可调工作区、精确时间编辑、质量筛选、可追溯的修改和导出 |

### 2.2 首次生成字幕

当前：启动台选目标，缺依赖进入配置，用户再回到入口，导入文件，选择模型与语言，运行。新手引导能辅助首次配置，但首页直接拖入这条路径尚未形成同样完整的闭环。

建议：导入即建立草稿，目标选择驱动依赖检查，缺什么只展示对应修复入口；完成下载或服务测试后自动回到原草稿。离线、本地优先和已有 API 服务分别提供起步路径。推荐模型同时展示适用语言、下载体积与本机兼容状态，避免只给技术名称。

验收：首次使用者拖入一段视频，配置过程中切页并返回，视频仍在；只做原文字幕时不要求配置翻译或配音。

### 2.3 下载到成片

当前已有：链接解析、下载、官方字幕跟随、将选择的产物带入任务向导。下一步应让用户看到实际获取的字幕语言、字幕来源、是否有时间轴，以及后续任务将使用哪一份。

建议：下载结果内直接选后续产物目标；同一任务上下文持续显示源视频、选用字幕和语言。人工校对点在启动前明确，并在任务等待时显示“需要你确认字幕”，同时提供进入和继续操作。

验收：带官方字幕的下载不要求重复转写；切换字幕来源后，流程摘要同步变化；人工确认完成后续跑同一任务。

### 2.4 批处理与参考文稿

当前多视频独立文稿匹配、同名匹配、行内候选与全局兜底已有实现。进一步优化应集中在让自动匹配结果可检查，而不是再增加一个复杂配置入口。

建议：每个视频清楚显示字幕来源与文稿来源，区分“同名自动匹配、手动指定、全局文稿、未指定”；批次头部汇总冲突和未匹配数量。长路径通过详情或悬停展开，切换来源后能看到受影响范围。

验收：多个视频混合全局文稿、独立文稿与未匹配文稿时，用户在运行前可准确判断每个视频使用什么。换全局文稿不会让已有行级绑定的含义变得模糊。

### 2.5 编辑、保存与重做

应区分四件事：保存任务草稿、保存字幕修改、生成配音缓存、导出最终文件。现有页面分别承担这些操作，但没有共同的状态表达。

建议把“未保存、保存中、已保存、保存失败”作为统一状态，另用“待校对、待确认、处理中、完成、部分失败”表达处理状态。更改字幕后，应说明对应配音或成片是否需要重生成；优先复用现有配置快照和会话 ID，不必先新建庞大项目系统。

验收：用户在任何编辑入口都能判断改动是否落盘；重新打开同一任务，能定位到原文件与未完成阶段；重试失败阶段时不误导为全流程重新收费或重新计算。

## 3. 全局布局与视觉规范

设计方向为实用型媒体工作台。保留已批准的 Studio Blue 主色和现有字体 token，采用中性色背景与有限的成功、警告、错误色。技能中偏展示型页面的装饰布局、特殊字体建议不适用于本产品，本报告不建议增加装饰性背景、斜切布局或营销式大标题。

| 维度 | 观察 | 建议 | 优先级 |
| --- | --- | --- | --- |
| 信息层级 | C+V：面板标题、说明条、内部配置容器叠加，部分页面边框层级较多 | 页面内容以工作区和分隔组织；只对独立工具、预览和重复条目保留必要边界，减少卡片嵌套 | P2 |
| 内容密度 | C+V：主工作台紧凑，工具箱留白明显更大，设置是居中长表单 | 形成任务队列、编辑器、资源主从、设置表单四种页面模板；统一间距与操作条，不强迫全部页面同形 | P2 |
| 字号 | C：导航 11px，部分辅助文本 10 至 11px；V：密集灰字扫描负担高 | 主操作和正文可从 13 至 14px 评估；10 至 11px 仅用于非关键元信息，提供紧凑与舒适密度评估 | P2 |
| 颜色 | V：深色界面辨识度较一致，但弱文字和多层相近灰色需要验证 | 主色用于选中和主操作；错误、等待、成功同时用文本和符号；测量实际对比度后调整 token | P2 |
| 字体与数字 | 已有品牌与字体基础；路径、时间码和模型名混排 | 保留正文体系；时间码使用等宽数字；文件路径可复制、末尾可识别；不靠缩字解决长内容 | P2 |
| 64px 导航 | C：52px 宽的导航项装 11px 标签；英文长词存在适配风险 | 保留宽度，使用一致短标签与完整名称提示；验证英文换行、焦点与选中态，避免字跑出热区 | P2 |
| 控件语义 | 多数使用 Lucide 与标准组件；仍有点击式 div 和仅图标无名入口 | 工具操作用图标按钮与可访问名称；互斥模式用分段或单选；布尔值用开关；精确数值允许键入 | P1/P2 |
| 主操作位置 | V：配音开始在顶部、合成在底部、工具箱在右下 | 同类页面统一行动区；编辑器播放与编辑工具就近，生成和导出动作保持可见，并明确当前阶段 | P2 |
| 预览 | 已有视频、字幕渲染和合成时间轴；文档截图中的视频为演示素材 | 验收使用真实横屏、竖屏、长字幕和双语素材，检查所见与实际导出一致性，不能凭演示图判断 | P1/P2 |
| 空态 | C+V：已有统一 StepGuide，但部分页仍有较大说明与重复提示 | 空态聚焦文件入口或必要选择；导入后收起引导；让当前状态、示例或实际产物承担说明作用 | P2 |

窗口适配以 Electron 实际支持范围为准：[主窗口](../main/background.ts) 默认 `1280 × 900`，最小 `1024 × 700`。优先验证最小窗口、常用笔记本窗口和 1920px 桌面，并覆盖系统缩放与中英文。手机宽度不应成为桌面应用首轮改版的验收目标。

固定宽度属性区需要与可用内容宽度共同决策。1024px 窗口扣除导航、332px 属性栏和间距后，预览剩余空间有限；建议支持折叠属性区或明确的紧凑模式。工具箱 `overflow-hidden` 和固定右栏的组合需要重点检查纵向可达性，目前不宣称已经发生遮挡。

## 4. 逐页评估

### 4.1 启动台 `/home`

依据：[页面](../renderer/pages/[locale]/home.tsx)、[配方](../renderer/lib/recipes.ts)、[历史截图](static/img/v3/launchpad/home.webp)。

已有：结果导向的配方卡、拖放导入、最近任务、环境就绪度、快捷工具和自定义流程。

- P1 / C：先完成 R03 与 R05，使入口描述、依赖检查和实际流程一致。
- P2 / C+V：配方卡、侧栏工具、全局导航重复出现校对、合成、配音入口，但“新建一条流程”和“单独处理文件”的差异不够直接。建议配方保留为创建入口，近期工作区优先承接已有任务；独立工具用明确类别区分。
- P2 / V+H：首页上方配方和就绪度占据较大空间，熟练用户可能更关心待确认与失败任务。建议无任务时优先创建，有历史时优先待处理，并允许固定常用配方；不要恢复与最近任务重复的“继续上次”卡片。
- P2 / C：模型、GPU、翻译、配音的整体就绪不能等同于当前目标可执行。就绪度应跟随选定目标，CPU 可运行时不应暗示 GPU 是必需条件。

验收：新用户可以直接从文件进入推荐路径；老用户可从首屏定位等待确认或失败任务；同一任务的等待状态在首页和任务页一致。

### 4.2 新任务向导 `/tasks/new`

依据：[TaskWizard](../renderer/components/tasks/wizard/TaskWizard.tsx)、[ManuscriptControl](../renderer/components/tasks/ManuscriptControl.tsx)、[历史截图](static/img/v3/wizard/new-task.webp)。

已有：文件与字幕配对、独立参考文稿、输出目标组合、字幕/配音/合成配置、人工确认点、保存配方。它实际是可组合的单页任务构建器，不需要为了名称机械改成多页向导。

- P1 / C+H：补齐 R08 的完整草稿，尤其保留文件配对、文稿来源和当前目标。配置服务或切回首页不能要求重建输入。
- P1 / C：将人工确认阶段纳入处理流程摘要。勾选“成品视频”后，应明确最后会得到哪些字幕、音频或视频文件。
- P2 / C：目标多选会增加下方配置区，增加滚动和回查负担。按开启的阶段展开对应配置，在可见区域保留文件数、输出目标和阻断原因摘要；无需永久重复大量说明文字。
- P2 / C：配方、全局默认、当前配置和任务快照容易混淆。将当前来源和已修改状态简洁表达，允许恢复配方默认；保存配方只保存可复用设置，任务草稿保存具体输入。
- P2 / C+H：混合视频、字幕和文稿的配对结果应可批量扫描。优先给出未匹配/冲突筛选与行级修正，不能只靠瞬时 Toast 提醒遗漏文件。

验收：开启全部输出后仍可定位开始按钮与阻断原因；修改配对后切页可恢复；用户能说清哪份输入跳过转写、哪份使用全局文稿。

依据：[设置页](../renderer/pages/[locale]/settings.tsx)、[自定义语言](../renderer/components/settings/CustomLanguageManager.tsx)、[历史截图](static/img/v3/settings/settings.webp)。

已有：界面语言、更新、休眠与关闭行为、存储目录、代理、下载源、处理参数、日志和高级选项。部分字段即时保存，部分在失焦后保存。

- P2 / C+V：长单列表单适合少量选项，目前内容已多。增加可搜索的分组导航：常规、存储、网络、处理默认值、高级与诊断；分组用页面分区，避免继续堆叠大型卡片。
- P1 / C+H：即时写入与失焦写入应有一致的保存反馈；字段校验失败保留用户输入，并说明有效值。不要添加一个全局保存按钮却仍让部分字段即时生效。
- P1 / C+H：存储根目录改变与文件迁移是不同操作，现有界面已经有不自动搬迁的说明。改进为可检查的当前目录、预计影响和迁移结果；先展示占用/引用情况，再决定是否值得建设迁移功能。
- P1 / H：清空路径、清缓存、重置参数等按钮命名必须对应实际作用。删除数据前展示范围；后台任务使用中的资源要按现有任务机制处理，不能仅靠模糊的“清除”。
- P2 / H：高级并发、网络和模型参数标明作用范围与生效时机；支持单组恢复默认。自定义语言输入校验与删除引用提示应与任务语言选择保持一致。

验收：搜索可直达代理与存储设置；修改失败不会显示已保存；切换存储位置后能判断旧文件是否仍在及当前读取位置。

### 4.15 旧路由与兼容入口

`/resources`、`/modelsControl`、`/translateControl` 是历史兼容入口，与 `/engines`、`/translation` 的实际功能页合并评估。应保留重定向兼容，并验证 locale、原选择、外部深链接与任务返回上下文；不要将其重复当作待重新设计的新页面。

## 7. 建议实施顺序

### 第一批：保存与反馈可信

交付范围：R01、R02、R04、R05、R06、R07。先通过少量明确修复解决已确认问题，同时建立后续改版可复用的行为基线。

| 工作 | 主要边界 | 完成条件 |
| --- | --- | --- |
| 校对保存与离开保护 | 校对页、编辑器、公共导航、IPC 响应消费 | 所有离开路径一致；保存失败不离开、不报成功；区分保存内容与保存批次 |
| 就绪状态 | Layout、已有环境检测与服务状态 | 检测中、缺模型、运行时失败、CPU 可用、云服务配置等状态表达准确 |
| 配方人工确认点 | 配方、启动台文案、向导流程摘要 | 默认保留字幕确认；入口与运行后等待行为一致 |
| 帧率预设 | SubtitleSyncPanel 与对应计算验证 | 精确帧率定义一致；一小时测试点无当前预设误差 |
| 双语拖入 | BilingualSubtitlePanel、现有文件导入能力 | 点击、拖入、键盘入口可用，非法文件有反馈 |

第一批不要求统一所有页面视觉。跨导航保护需要覆盖全局入口，不能只加一个校对页返回提示就视为完成。

### 第二批：任务连续性与配置闭环

交付范围：R03、R08，以及任务、校对、配音、合成、下载之间的上下文表达。

- 建立最小任务草稿，保存输入、目标、配对、文稿来源与局部配置；进入配置前写入草稿引用。
- 配置成功返回原任务；配置未完成也能返回，不丢弃输入，并准确保留阻断状态。
- 复用已有 WorkItem、configSnapshot、配音会话和产物信息，统一保存与处理状态；先改善用户可见规则，不先重写所有存储模型。
- 明确源字幕修改对配音与成片的影响，统一产物打开、重试和返回原任务的入口。

完成条件：首次字幕生成、下载后制作、混合输入批处理三条链路都能跨页完成，且不要求重复选择已导入文件。

### 第三批：视觉与交互一致性

交付范围：R09、R10、页面模板、导航长文案、字段保存反馈、工具结果区和公共弹窗。

- 先统一控件语义、图标名称、国际化、间距与可滚动区域，再调整装饰层级。
- 工具箱使用与主工作台一致的输入/行动/结果模式；设置增加分组检索，资源侧栏收敛常用项。
- 以当前 Studio Blue token 为基础，实测深浅主题对比度与缩放，不另起一套品牌视觉。
- 统一同类编辑器的属性区折叠与主操作位置；先验证校对、配音、合成三个代表页，再扩展。

完成条件：最小窗口和中英文下，没有不可达主操作、文本遮挡、未命名图标或仅鼠标可用的核心入口。

### 第四批：专业编辑增强

候选范围：问题字幕筛选、可调分栏、播放循环与定位、配音时长比较、必要时的音频波形与时间轴编辑、批量产物整理。

这些属于 P2/P3 的产品增强。先观察高频工作实际耗时再排序；不要为了“看起来专业”先建设完整非线性剪辑器。专业感主要来自操作可预测、时间精确、结果可恢复和批量处理稳定。

## 8. 验收计划与衡量方式

以下是后续实施的验证计划，本次分析未执行这些实机用例。

| 场景 | 关键检查 |
| --- | --- |
| 全新配置生成原文字幕 | 导入保留；仅检查所需依赖；完成配置回原任务；首个产物可打开 |
| 无翻译服务时启动双语任务 | 目标、语言和文件不丢；配置失败可返回；成功后原任务可继续 |
| 默认配音成片配方 | 启动前看见字幕确认点；运行后等待状态清楚；确认后同一任务继续 |
| 校对未保存后离开 | 页内返回、侧栏、命令面板、历史导航、关闭窗口分别验证；保存/放弃/取消结果正确 |
| IPC 保存失败 | 模拟 `success: false` 与异常两类失败；不提示已保存，不清除修改，不退出编辑 |
| 长字幕与混合批次 | 多语言长文本、上千字幕、数十素材、独立/全局文稿、配对冲突均能扫描与修正 |
| 配音恢复与局部重做 | 恢复会话；换音色或改句子；检查有效缓存、失败重试、过长提示和导出版本 |
| 字幕精度与合成 | 23.976/24/25 fps；字幕越界；横屏、竖屏、双语、缺字体、硬字幕与软封装 |
| 下载到后续任务 | 多语言官方字幕、失败条目、Cookie 过期；产物选择正确传入向导 |
| 工具箱完整状态 | 8 工具的空态、导入、处理、成功、失败；适用工具的取消、切页和恢复 |
| 桌面布局 | 1024 × 700、1280 × 900、1440 × 900、1920 × 1080；中英文、深浅主题、系统缩放与长路径 |
| 跨平台与可访问性 | Windows 标题栏与字体；macOS 窗口行为；Tab 顺序、焦点可见、图标名称、读屏状态反馈 |

建议先用 3 至 5 位目标用户做任务观察，记录基线，再评价改进。无需为了这次评估先接入线上埋点；可使用本地计时、观察记录和匿名汇总。

| 指标 | 记录方式 | 期望方向 |
| --- | --- | --- |
| 首次可用产物耗时 | 从导入到首次打开结果；单独记录下载/计算等待和用户操作时间 | 降低操作时间与求助次数，不把网络或模型速度误算成 UI 改善 |
| 重复选择次数 | 一条链路中重复选择同一文件、模型、语言或音色的次数 | 减少；配置往返不要求重复导入 |
| 恢复能力 | 未保存离开、保存失败、重新打开任务的用例结果 | 已定义用例全部通过，不发生静默丢失或成功误报 |
| 状态理解 | 用户能否指出当前阶段、阻断原因、保存状态和下一步 | 在任务区直接判断，不需依赖日志解释 |
| 错误恢复时间 | 从失败提示到完成有效修复或重试 | 缩短，减少跳页与重新配置 |
| 编辑效率 | 在相同素材上校对、换音色、调整字幕位置的操作次数与时间 | 高频路径减少浮层和重复滚动 |
